    主要 CTA
    開始提醒（次要：返回、取消）
    下一步
    /reminder，計時開始
    本輪變更 · 併入原步驟 3

    按鈕上方必須就地顯示原 S-06 的必顯內容，否則會違反 AC-34 Scenario C 「使用者須檢查完整部位摘要才按下開始提醒，系統不得加入摘要中未揭露的部位」：

    • 情境與水上狀態
    • 追蹤部位大群組與每部位方法（目前已顯示部位，方法尚未）
    • 產品 snapshot 摘要、曝曬前等待、較短補擦標示、耐水標示

    快速提醒會自動寫入建議部位、使用者沒有逐一挑選， 所以這份摘要是唯一的揭露點，不能省。

三、帳號策略：P0 不做登入

問卷顯示多數人不想註冊、少數想保留產品資訊。這正是 PRD §5.5「訪客優先、可選升級」 要解決的形狀，而該節已完整設計，不需要新發明。

  • 登入不會讓提醒更準，只影響保存與同步

    PRD §5.5.1 明訂：登入與否不得改變 UVI、提醒公式、期限資格或衛教內容。 所以「想註冊的人」要的不是功能，是不要弄丟資料—— 這件事在 P0 有三個不需要帳號的答案。

    防曬晴報員PRD.md §5.5.1

  • P0 的三個答案：安裝、資料管理、誠實告知

    /install 讓 PWA 安裝後資料更耐久；/settings/data 讓使用者看得到也清得掉；存產品後明確說「只保存在這台裝置」。三頁都在規格內、都還沒做。

    P0-19 · P0-20

  • P0 階段不得出現登入 CTA

    §5.5.2 第 6 點禁止「登入後提醒更準」這類文案；功能未上線時不得掛登入入口誘導。 帳號登入登出照原計畫留在 P1，屆時用 §5.5.2 已寫好的時機與文案。

    防曬晴報員PRD.md §5.5.2

  • 建議加入本機匯出

    P0-19 目前只有「查看及清除」。對想保留產品資訊又不想註冊的人， 匯出是沒有帳號時唯一的自救手段。比加登入便宜得多，不違反任何安全條文， 但需要擴 §8 與 P0-19 的範圍——待裁決。

    P0_RELEASE_MANIFEST.md §8

四、仍待處理

  • 產品資料模型要擴充，但購買日期與備忘不得進 reducer

    product.ts 目前只有會影響提醒的標示欄位，且 expiryStatus 是三值列舉不是日期。需新增品類、購買月份、真正的到期日、備忘、封存時間。 其中購買日期與私人備註已被規則明文禁止參與 reducer， UI 必須讓使用者知道填了不會改變倒數。

    P0_REMINDER_RULE_DECISION_TABLE.md §4.4

  • 墨鏡沒有對應的身體部位

    BODY_ZONE_V3 全是皮膚部位，眼睛不在其中。墨鏡進來後不會有任何提醒行為， 純屬紀錄。衣物則不同——它已是 methodComponent，有實際語意（覆蓋期間不倒數）。 兩者在同一份清單裡但行為不同，分區呈現是為了避免誤解。

    packages/contracts · BODY_ZONE_V3

  • Q&A 每一則都要標審查狀態

    防曬知識內容會踩到 PRD §13 的衛教內容治理，Copy Deck 的 CONTENT_REVIEW／MEDICAL_REVIEW／MARINE_REVIEW 三種閘門都可能觸發。「需要再詳細」的具體意思是：先列題目清單，逐則標審查類別。

    防曬晴報員PRD.md §13 · P0_COPY_DECK.md §1

  • 最近事件時間軸仍未實作

    PRD §5.7.2 與 S-07 資訊順序第 7 項都要求，程式碼裡沒有任何 timeline 元件。 它是「讓使用者理解狀態為何改變」的載體，缺了提醒就是黑箱。

    防曬晴報員PRD.md §5.7.2 · ReminderPage.vue

  • P0-04 的複雜度需要更具體的描述

    ZoneProtectionForm 已依 AC-34 的大群組收合。若仍覺複雜， 可能是預設全展開、方法選項過多，或改動後看不出差異——方向不同，改法不同。

    ZoneProtectionForm.vue · AC-34
