## 二、8 個從未被 `var()` 引用的 token

**先澄清一件事**：這 8 個在 `DESIGN.md` 的色彩表裡**都有定義**（第一次用 token 名 grep 沒中，用 hex 反查才找到——文件寫的是 `{colors.accent-apricot}`，程式碼叫 `--color-apricot`）。所以它們不是無依據的殘留，而是**規範定義了、程式碼沒有套用**。

### A. 因 2026-08-23 設計變更而失效（4 個）

`DESIGN.md` 第 662 行記著：

> **2026-08-23 變更**：原本規定為濃縮咖啡深色卡片（`countdown-panel`）加進度環。wireframe 改為畫布上的平面版本，使用者裁決採用 wireframe。層級改由**字級**承擔……不再依賴深色表面的對比。

深色倒數面板整套被放棄了，但為它準備的 token 留了下來：

| Token                           | `DESIGN.md` 寫的用途               | 現況                                    |
| ------------------------------- | ---------------------------------- | --------------------------------------- |
| `--color-surface-dark-elevated` | 深色區塊內的控制項與**進度環軌道** | 進度條軌道實際用 `--color-surface-card` |
| `--color-surface-dark-soft`     | （深色表面變體）                   | 無深色表面可用                          |
| `--color-on-dark-soft`          | 深色表面上的次要標籤               | 無深色表面可用                          |
| `--surface-inverse`             | 語意別名 → `--color-surface-dark`  | 同上                                    |

`--color-apricot` 的「**倒數進度環**」用途也一併失效——進度條現在用 `var(--tone-color, var(--color-tracking))`，是 2026-08-29「狀態必須同時有色彩、圖示與文字」那次的做法，是有意的。

**這一類不是「忘了套用」，是設計已變更但色彩表沒跟著收。**

### B. 規範仍有效，只是從未套用（2 個）

| Token                     | `DESIGN.md` 寫的用途                         | 現成的落點                                         |
| ------------------------- | -------------------------------------------- | -------------------------------------------------- |
| `--color-blush` `#D79A92` | 「衛教引言與分類細節；**永遠不作為行動色**」 | 衛教首頁與分類頁目前完全沒有用到它                 |
| `--color-amber` `#D9A35F` | 「徽章、**SPF 標記**、陽光母題。不用於內文」 | `GearForm.vue` 有 SPF 欄位與 `.affects-badge` 徽章 |

`--color-apricot` 除了進度環，還被指定為「插圖筆觸、小面積高光」——那部分仍然有效。

**這一類才是真正與資料概況卡同型的問題：規範寫了具體落點，程式碼沒做。**

### C. 一個特例

`--color-mauve` `#8C6F7A` 沒有被 `var()` 引用，但 `styles.css` 自己的註解說明了原因：`--color-saved` 是**同值複製**而不是 `var(--color-mauve)`。

> 2026-08-26 從綠色 `--color-success #147d64` 改成藕紫（與 `--color-mauve` 同值），並改名……

同一個顏色寫兩份，改一處不會連動。這是可以收斂的，但屬於另一個問題（重複，不是未使用）。

## 三、為什麼現有守門抓不到

`packages/ui/src/tokens.test.ts` 守的是 **`DESIGN.md` → `styles.css` 的單向一致性**：文件裡有的 token，`styles.css` 必須有而且值相同。

它**沒有反向檢查**，所以「`styles.css` 定義了、但畫面上沒有任何地方用」不會紅。這次的 8 個 token 全部通過既有測試。

**同樣的盲點也存在於 class、圖示與元件**——只是這三類目前剛好是乾淨的。

## 五、重跑方法

掃描邏輯（可重建）：

- 走訪 `apps/web/src` 與 `packages/`，排除 `node_modules`／`dist`／`.worktrees`
- **先剝註解**（`/* */`、`//`、`<!-- -->`），否則註解裡提到的名稱會被誤算成「有使用」
- class：從 `app.css` 抓 `.xxx` 宣告，比對所有 `.vue` 的內容
- token：從 `styles.css` 抓 `:root` 的 `--xxx:`，比對 `var(--xxx)` 是否出現在任何 `.vue`／`.ts`／`.css`
- 元件：檔名在其他檔案出現次數 ≤ 1（只有自己）即為孤兒——**注意路由用動態 import 字串，要另外比對 `router/index.ts`；`pages/` 底下的元件也可能被同目錄的其他頁面 import**（`EducationNotFoundPage` 就是這樣，第一版掃描誤報過）
- 圖示：從 `icons.generated.ts` 抓 key，比對是否出現在程式碼中
