### 為什麼裝備詳情值得單獨記一筆

**它不是版面調整，是少了一層。** 使用者的入口是「多一個跳轉頁面蠻奇怪的」，查證後成因更深：`ProductDetailPage` 幾乎是編輯頁的子集——`GearForm` 底部本來就有「移至收納／恢復使用／刪除」（含二次確認），欄位也都帶著現值，詳情頁獨有的只剩一張唯讀規格卡。

成本與頻率原本是**反的**：最常做的「看一眼」要跳一頁，要改東西得跳兩頁（清單 → 詳情 → 編輯）。改成抽屜後看是 0 次跳轉，編輯 1 次（表單需要整頁，那一次省不掉）。

**抽屜的適用界線（同一天做過兩次相反的判斷，兩次都對）**：同一天稍早否決了「包裝標示改抽屜」——那裡是照著瓶身抄的資料輸入，會邊看邊改、還有「要不要存」的問題；這裡是看規格加選一個動作，沒有輸入也沒有草稿。**判準是「有沒有輸入與草稿」，不是「內容多不多」。**

考慮過但沒採用的第三案：砍掉詳情頁、清單直接進編輯頁。最省，但「想看一眼」會落進一張有 `儲存` 的表單裡，容易誤改，掃視也比唯讀卡差。
