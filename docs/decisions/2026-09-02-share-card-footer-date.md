# 分享卡頁尾：安全註記換成日期

**日期**：2026-09-02
**裁決者**：使用者
**狀態**：已套用

## 裁決

分享卡（畫面預覽與輸出的 PNG）頁尾原本是安全註記，改成**卡片日期**。

同時把日期從頁首拿掉——兩邊都留會變成一張卡上有兩個日期。

## 被移除的是什麼

原本的頁尾文字有兩種形態：

| 情況         | 原文字                                                                                   |
| ------------ | ---------------------------------------------------------------------------------------- |
| 沒有 UV 資料 | 這是協助記得補擦的紀錄，不是安全曝曬時間或防護效果保證。                                 |
| 有 UV 資料   | （同上）＋ UV 資料來源：中央氣象署 F-D0047-091。                                         |

## 代價（記錄在案，不是反對）

**這段文字在 `DESIGN.md` 第五節的「不可隱藏」清單上。** 該清單的立場是：健康與安全邊界不得藏在互動之後，也不得因為版面理由被移除。

分享卡是這條規則裡**最需要它的場景**，因為圖會被轉傳，收到圖的人沒有這個 App 的脈絡——他看到的是一張列著 SPF、耐水分鐘數、補擦間隔的卡片，沒有任何一句話說明「這是紀錄工具，不是防護效果保證」。

原本有兩條測試守著這件事（`gearShareCard.test.ts` 的「安全註記不可省略」），已隨本次改動移除。**測試檔裡保留了一段說明指向這份文件**，避免下一個人以為那條規則從來不存在。

## UV 出處一併消失

「中央氣象署 F-D0047-091」跟著那段一起沒了。這一項的代價較低：

- 資料集代號 `F-D0047-091` 已被 `2026-09-02-taiwan-copy-optimization-audit.md` §1.4 判定為對一般大眾無意義，五日預報卡那邊也已經拿掉
- App 內的五日預報頁仍然標示資料來源，出處沒有從整個產品消失，只是不印在分享圖上

若日後認為分享圖仍需標示來源，最小的做法是在日期那一行後面補「資料來源：中央氣象署」，不要把代號加回來。

## 日期用哪一天

| 情況         | 日期             |
| ------------ | ---------------- |
| 有進行中提醒 | 提醒的起始日     |
| 沒有提醒     | 今天（做卡片的日子） |

兩種模式都有日期。理由是轉傳：收到圖的人需要知道這份清單是什麼時候的。

這推翻了 2026-09-01 的「『我的防曬裝備』不帶日期」——那次的考量是不要讓一張通用清單看起來像當日紀錄，本次裁決認為可追溯性更重要。
