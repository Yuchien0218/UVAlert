# 「本機資料管理」與「跨裝置同步」合併回一張卡

**日期**：2026-08-29（Asia/Taipei）
**狀態**：待裁決——本文件是盤點與建議，**不是已確認的決策**。
**用途**：「更多」頁有一組卡片可以合併，而且合併不是新提案——是回到 `DESIGN.md` 與 Sitemap 本來就訂好的設計。
**範圍**：只動「更多」頁的入口卡與 `/settings/*` 的頁面組織，不改任何同步或本機資料的行為、契約與資料模型。
**權威性**：低於 `DESIGN.md` 與 `2026-08-15-redesign-sitemap-userflow-current.md`。本文件指出實作與它們的落差。

## 一、落差：文件訂 6 張卡，程式碼拆成 8 張

`DESIGN.md` 第五節「更多」訂的排序：

> 通知設定 → 防曬衛教 → **本機資料與隱私** → 問題回報與意見回饋 → 安裝到主畫面 → 說明與關於

Sitemap §2.4 講得更具體：

> 通知設定與本機資料與隱私都採**單頁分區**；**本機備份放第一層，Google 同步放次要區塊**。

但實作把「本機資料與隱私」拆成了兩張卡、兩個頁面，底下還掛第三頁：

```
更多 → 本機資料管理  /settings/data          （328 行）
更多 → 跨裝置同步    /settings/sync          （218 行）
            └→ 登入與雲端資料 /settings/account-data （175 行）
```

Sitemap §2.4 已經記過「實作是八張卡不是六張」這個落差，但當時只是**記錄**，沒有裁決要不要收回去。

## 二、這個拆分有具體成本

`DataSettingsPage.vue` 上有一張卡（`cloud-data-link-title`）是**純粹為了處理拆分而存在的**：

> **雲端資料請到另一頁管理**
> 本頁只處理這台裝置的本機資料。若你有登入並使用同步，請到登入與雲端資料頁管理。
> 〔管理登入與雲端資料〕

它沒有任何功能，全部的工作就是解釋「為什麼你要找的東西不在這裡」。**如果兩頁是一頁，它不需要存在。** 這是拆分製造出來的問題，然後又花了一整張卡的版面去補救。

## 三、對「更多」頁清爽度的實際效果

「更多」頁目前**實際只渲染 6 張卡**——`/help` 與 `/special-situation` 被 `MorePage.vue` 的 publishable gate 過濾掉了（兩者內容都還沒上線）。

| 做法 | 版面節省 |
| --- | --- |
| 合併掉一張卡 | **一整張卡 82px ＋ 間距** |
| 刪掉 B9 分類表裡唯一能刪的那段說明 | 約 24px |

**合併一張卡的效果，大於把所有可刪的說明文字都刪掉。** 這也是為什麼這件事應該排在 B9 之前——否則 B9 才剛把兩張卡的圖示放大、文字調好，合併時全部重來。

## 四、建議

**把「跨裝置同步」併進「本機資料與隱私」，`/settings/account-data` 維持巢狀。**

合併後的分區，直接對應 Sitemap 的「本機備份放第一層，Google 同步放次要區塊」：

| 區塊 | 內容 | 來源 |
| --- | --- | --- |
| 這台裝置儲存了什麼 | 資料概況 | `DataSettingsPage` |
| 匯出 | 本機備份 | `DataSettingsPage` |
| 清除 | 三種清除範圍 | `DataSettingsPage` |
| ─── 次要區塊 ─── | | |
| 跨裝置同步 | 登入模式、同步狀態、內容預覽 | `SyncSettingsPage` |
| 登入與雲端資料 | 仍是獨立頁，從同步區塊進入 | `AccountDataPage`（不動） |

`account-data` 保持獨立頁是**照 Sitemap 原本就訂的**——§2.4：「另有 `/settings/account-data`（登入與雲端資料），**從『跨裝置同步』頁進入，不是獨立入口卡**」。合併後它改從同步區塊進入，層級不變。

### 為什麼不三頁全併

三頁合計 721 行。全併會做出一個很長的頁面，而 `account-data` 的內容（登出、清除雲端資料）是**不可逆操作**，把它和本機資料的清除操作放在同一頁，兩組「清除」會互相混淆——這正是 `DESIGN.md` 第六節「每頁只保留一個最主要任務」要避免的。

## 五、另一組：現在不要動

**常見問題（`/help`）＋ 特殊狀況（`/special-situation`）** 在原本的 6 張清單裡對應「說明與關於」一張，看起來可以合併。但：

- **兩張現在根本沒顯示**——被 publishable gate 過濾
- `/help` 的兩則主題 2026-08-23 已核准，但 `HelpTopicPage.vue` 還沒接內容（只有 `v-if="!publishable"`，沒有 `v-else`）
- `/special-situation` 的文案是 `BLOCKED`，等台灣醫療與法務核准

**現在合併等於在對不存在的東西做資訊架構。** 等內容真的要上線時再一起決定。

## 六、不建議動的四張

通知設定、防曬衛教、安裝到手機桌面、問題回報——各自是獨立的關注點，沒有可合併的對象。
