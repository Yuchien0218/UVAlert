# B8 語意字級量表設計規格

**日期**：2026-08-27（Asia/Taipei）

**狀態**：產品端已確認，待撰寫實作計畫

**範圍**：全站字級 token、舊 token 的語意遷移、長文排版節奏與視覺驗證；不包含一般文案、圖示重設或卡片結構重做

## 一、問題與目標

目前 `DESIGN.md` 有 14 級編輯型量表，程式碼則有 8 個命名與數值不完全對應的 `--font-size-*` token。部分 token 是先前從散落值收斂出的暫存桶，同名不等於同一語意，導致後續很難判斷元件該用哪一級。

B8 不把 14 級完整搬進產品，而是建立較少、角色明確的產品量表。目標是讓頁面層級可預測、降低 scoped CSS 的自行決定，同時保留真正需要響應式大字的核心讀數。

## 二、核准量表

正式程式碼以 `rem` 表示；下表 px 為根字級 16px 時的設計基準。

| 語意 token                  | 基準值 | 用途                                                  |
| --------------------------- | -----: | ----------------------------------------------------- |
| `--font-size-page-title`    |   28px | 每頁唯一主標題、設定流程主標題                        |
| `--font-size-section-title` |   20px | 頁面區段、Dialog／Bottom Sheet、文章主要章節標題      |
| `--font-size-card-title`    |   18px | 卡片標題、欄位群組標題、文章次級標題                  |
| `--font-size-body`          |   16px | 正文、按鈕、輸入內容與一般操作文字                    |
| `--font-size-supporting`    |   14px | 欄位標籤、helper text、次要資訊與可跨行閱讀的補充文字 |
| `--font-size-caption`       |   12px | 短註腳、時間戳、eyebrow、badge；不承載長段說明        |
| `--font-size-nav-label`     |   12px | 主要底部導覽標籤                                      |

`caption` 與 `nav-label` 數值相同但角色不同，保留兩個 token，讓字重、行高、字距和未來調整可以獨立演進。

## 三、遷移規則

- 不把舊 `title`、`title-sm`、`title-md`、`section-title`、`label` 做機械式一對一改名。
- 逐一依元件的實際角色選擇新 token；同一個舊 token 可以遷移到不同的新角色。
- 一個視覺區塊若沒有清楚的標題層級，不為了保留舊外觀新增例外 token。
- 多行說明不得降成 `caption`；能持續閱讀的次要文字至少使用 `supporting`。
- 按鈕與輸入內容維持 16px，避免行動瀏覽器自動縮放與可讀性下降。
- 將 `DESIGN.md` 的 typography 規格改成同一套七角色量表，移除「文件一套、程式碼另一套」的漂移。

## 四、保留的元件級例外

- 首頁倒數、UVI 數值、設定流程的關鍵數字保留各元件既有的響應式 `clamp()`；這些是資料展示，不強塞進一般文字量表。
- 五日預報在極窄螢幕的相對縮字屬於版面保護，可保留，但需在視覺驗證中確認仍可讀。
- 衛教文章正文維持 16px、既有長文 measure 與寬鬆行高；B8 只強化「標題靠近下方內容、遠離上一段」的歸屬節奏。
- 文章底部的一般聲明使用 `caption` 與現有合格的 muted 文字色，並以較大上方間距和正文分開；不新增對比不足的第五級文字色。

## 五、文章裝飾性波浪

採用已確認的 A 款「單一道柔和波浪」：低對比、圓端、置中，作為長篇衛教內容兩個主要段落群之間的停頓。

- 使用可重用的 inline SVG 或等效元件，`aria-hidden="true"`，不可加入可存取名稱。
- 一篇文章最多使用一至兩次，不在每個小標題前重複。
- 不用於設定頁、表單、卡片清單，也不取代正常的標題間距。
- 波浪只負責節奏，不傳達狀態、完成或風險意義。

## 六、明確保留與非範圍

- 資料設定摘要卡保留原版貫穿分隔線，不套用移除線條或 inset divider 方案。
- B8 不改寫標題、按鈕或警示文案。
- B8 不新增警示 icon、不改 icon 家族，也不進行全站 icon 放大；該方向另見 B9 規格。
- B8 不順便清理與 typography 無關的 spacing、顏色、陰影或死碼。
- 不以 `hanging-punctuation` 或負 margin 校正中文標點，避免不一致的瀏覽器支援與魔術數值。
- 若需要改善中文詞組斷行，僅能作漸進增強並另外驗證，不設全域 `word-break: keep-all`。

## 七、守門與驗證契約

- 擴充 `packages/ui/src/tokens.test.ts`，驗證七個語意 token 與 `DESIGN.md` 的值一致。
- 搜尋並消除被取代的舊 token 使用點；例外硬寫值必須有明確元件理由。
- 執行既有 `pnpm check`、格式與 lint 守門。
- 以 390×844 與 1440×1000 至少覆蓋首頁、setup、產品、地區、預報、衛教首頁／文章、資料設定、通知設定與 overlay／sheet。
- 視覺驗證需檢查：標題層級、換行、截斷、水平溢出、44px 操作高度、文章段落歸屬與波浪使用頻率。
- 另檢查 320px reflow 與瀏覽器 200% zoom，確認 12px 角色沒有被拿來承載必要的長段內容。

## 八、完成條件

只有在 token、`DESIGN.md`、測試與實際元件用法一致，且桌面／行動視覺矩陣完成後，B8 才能標記完成。設計稿或規格完成不等於正式介面已上線。
