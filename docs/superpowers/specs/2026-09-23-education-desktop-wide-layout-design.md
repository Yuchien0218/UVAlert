# 衛教三頁桌面寬版設計

日期：2026-09-23  
狀態：使用者已核准設計方向，待實作計畫

## 一、問題與目標

目前 `AppShell` 在所有頁面都使用 `--app-shell-max: 30rem`。這能讓提醒、設定與表單在桌面上保有接近手機的操作密度，但也使衛教頁既有的 `42rem`、`44rem` 內容上限無法真正生效；文章在桌面上仍像置中的手機版。

本次目標是讓下列三種衛教頁在桌面上使用較寬、適合閱讀與卡片瀏覽的版型：

- 防曬衛教首頁 `/education`
- 衛教分類頁 `/education/:category`
- 衛教文章頁 `/education/articles/:slug`

提醒、裝備、設定、表單及其他 App 頁面不在本次範圍內，繼續使用 `30rem` 外框。

## 二、採用方案

採用「由路由宣告寬版內容，AppShell 統一套用」的方案。

三個衛教路由新增相同的布林 meta 欄位 `wideLayout: true`。`AppShell` 讀取這項路由資訊，為外框加上具名寬版 class；該 class 在桌面斷點將外框最大寬度切換為既有的 `--content-max: 47rem`。

這個責任分配的理由是：

- Router 決定哪些頁面屬於寬版內容。
- AppShell 負責整個頁面的外框寬度。
- 各衛教頁繼續負責自身內容的 `42rem`／`44rem` 閱讀上限。
- 不讓子頁用負邊距或 viewport 單位突破父層，以免產生橫向捲動與邊界不一致。

## 三、響應式行為

### 手機與窄視窗

- 衛教三頁維持 `width: 100%`，不得比目前更寬。
- 沿用既有頁面 padding、安全區域與最小支援寬度。
- 不改變標題、卡片與文章的單欄閱讀順序。

### 桌面視窗

- 只在既有桌面斷點開始套用寬版外框。
- AppShell 最大寬度由 `--app-shell-max` 切換為 `--content-max`。
- 頁首、狀態提示與主內容共享同一外框，避免頁首窄、正文寬的斷裂感。
- 三個衛教路由原本已設定 `hideNavigation: true`，因此本次不改 BottomNavigation，也不需要建立第二套導覽寬度。

## 四、三種頁面的寬度責任

### 衛教首頁

- 外框可使用 `47rem`。
- 標題區仍遵守既有 `42rem` 上限。
- Hero 與分類卡片網格使用較寬的可用空間，不另外加入任意寬度。

### 衛教分類頁

- 外框可使用 `47rem`。
- 標題、封面及文章卡片列表沿用現有內部規則。
- 不改變分類資料、文章排序、發布閘門或連結行為。

### 衛教文章頁

- 標題、封面、摘要、審閱提示、正文與延伸閱讀維持既有 `44rem` 上限。
- 正文不撐滿 viewport，避免桌面長行降低閱讀舒適度。
- 不在本次調整字級、行高、段落間距或內容文案。

## 五、元件與資料邊界

本次不新增衛教內容元件，也不改變資料流。

- `router/index.ts`：三個衛教路由宣告寬版需求。
- `AppShell.vue`：由 route meta 推導寬版狀態並套用 class。
- `packages/ui/src/styles.css`：沿用 `--app-shell-max` 與 `--content-max`，不新增重複數值。
- 三個衛教頁：不修改；本次直接沿用其既有 `42rem`／`44rem` 內部上限。

這項變更沒有新的 props、emits、composable 或非同步資料流程。

## 六、不採用的方案

### 子頁突破固定外框

不使用負邊距、`100vw` 或 transform 讓衛教內容突破 AppShell。這會讓頁首、邊框和正文無法共用對齊線，也容易因桌面捲軸寬度產生橫向溢位。

### 全站改成寬版

不修改 `.app-shell` 的全域預設寬度。一般 App 頁面仍需要緊湊、手機型的操作欄寬；全站放寬會使表單、提醒與控制項失去既有密度。

### 新增另一組寫死寬度

不新增 `44rem`、`47rem` 的重複 magic number。外框使用現有 `--content-max`，文章內部繼續使用現有規則。

## 七、測試與驗收

### 自動化守門

- 三個衛教路由都必須宣告寬版 meta。
- AppShell 預設仍使用 `--app-shell-max`。
- AppShell 只有在寬版 class 與桌面斷點同時成立時才使用 `--content-max`。
- 非衛教路由不得意外取得寬版 class。
- 既有 typecheck、Vitest、ESLint 與 Stylelint 全部通過。

守門測試在完成後要做一次破壞驗證：暫時移除一個衛教路由的寬版 meta，確認測試會失敗，再還原實作。

### 瀏覽器驗收

至少檢查：

- 390px：三頁維持單欄、無橫向捲動。
- 768px：寬版開始生效時沒有突兀跳動或裁切。
- 1024px 與 1440px：外框置中，最大寬度不超過 `47rem`。
- 文章正文維持約 `44rem` 上限，段落行長沒有撐滿桌面。
- 衛教首頁與分類頁的卡片、封面、標題和返回操作維持正確對齊。
- 任選一個非衛教頁確認仍是 `30rem` 外框。

## 八、完成定義

只有在以下條件同時成立時，才能宣告完成：

- 三種衛教頁在桌面套用一致的寬版外框。
- 手機版沒有版面退化或橫向捲動。
- 其他 App 頁面仍維持原本外框寬度。
- 自動化檢查通過，且寬版守門已做破壞驗證。
- 已完成至少一輪真實瀏覽器的手機與桌面視覺檢查。
