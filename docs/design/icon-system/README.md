# UVAlert 圖示系統

## 工作流程

**幾何的真實來源是 Illustrator，不是程式碼。**

1. 在 Illustrator 畫圖示，畫布 24×24，匯出成 SVG 到 `icons/<id>.svg`。檔名必須對應 [`generate-icons.mjs`](../../../tools/icon-system/generate-icons.mjs) 的 `ICONS` 登記表裡的 `id`。
2. 跑一次建置腳本：

   ```bash
   node tools/icon-system/generate-icons.mjs
   ```

3. 腳本會就地正規化 `icons/*.svg`，並重新產生兩張預覽板。

### 腳本做什麼、不做什麼

**做**：把 Illustrator 匯出的格式改成可以直接 inline 進 Vue 的樣子——

- `#000`（以及 `#33291F`、`#2E2925`）換成 `currentColor`
- `<defs><style>` 裡的 CSS class 內聯到元素上，然後移除 defs 與 class 屬性
- 注入 `<title>`（中文標籤）、`data-icon`、`data-tone`、`role="img"`
- 統一強調色大小寫為 `#C1832E`、去掉 `stroke-width` 的 `px` 單位

**不做**：不碰幾何。路徑資料原封不動，腳本沒有能力也不應該改造型。

腳本是冪等的，重複執行結果相同，可以安全地隨時再跑。

### 為什麼要正規化

三個問題都會在 App 裡出事，而且都不是潔癖：

| Illustrator 匯出                  | 為什麼不能直接用                                                                                                                          |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `stroke: #000`                    | 設計系統要求墨色用 `currentColor`。寫死黑色的話狀態圖示無法繼承語意色，放在深色倒數面板上會變成看不見的黑塊。而且 `#000` 也不是系統墨色。 |
| `.cls-1` / `.cls-2` 放在 `<defs>` | 每個檔案都從 `.cls-1` 開始編號。同一頁 inline 兩個圖示時 class 會互相覆蓋，這是最難查的那種 bug。                                         |
| 沒有 `<title>`                    | 螢幕閱讀器讀不出圖示語意。                                                                                                                |

> **歷史**：2026-08-19 之前這支腳本是用 JS 函式產生路徑的，結果是「跑一次就把手繪成果整批蓋掉」，差一點真的發生。幾何歸 Illustrator 之後就沒有這個風險——腳本只讀檔、正規化、寫回。

## 一、造型語言

圖示的視覺 DNA 來自 06 播報印記 Logo：**實心圓點＋膠囊狀線條**。

- 畫布 24×24，四周保留約 2px 光學留白。
- 線條寬度固定 `2.5`，端點與轉角一律 `round`——渲染出來就是膠囊形，呼應 Logo 的射線。
- 需要強調的元素用實心填色，不用加粗線條來製造層級。
- 不使用尖角、不使用陰影、不使用漸層。

**UV 五級不畫圖示。** `FiveDayUvCard.vue` 已經同時顯示指數數字（如「11」）與風險等級文字（如「危險級」），數字本身就是不靠顏色也能區分的資訊，不需要額外的格數圖示重複同一件事。這條規則真正要防的是「沒有裸數字可看」的狀態（倒數四狀態），所以格數計量表只留給那裡。原本畫好的 5 個 `state-uv-*` 已從登記表與 `icons/` 移除，取捨原因見第十節。

### 為什麼狀態類不用琥珀金

倒數狀態在 `packages/ui/src/styles.css` 裡各有語意色（`--color-tracking` 藍、`--color-soon` 琥珀、`--color-due` 紅）。狀態圖示若寫死琥珀金會與語意色衝突。單色 `currentColor` 讓圖示自動繼承外層語意色，一份幾何走遍所有狀態。工具型圖示是同樣的道理——它們會出現在按鈕、連結、狀態列等各種語意情境裡。

## 三、不依賴顏色的區分方式

`docs/design/current-direction.md` 明訂「狀態必須同時有色彩、圖示與文字」。因此：

- **倒數／部位四狀態**用剩餘量計量表：追蹤中（三格）→ 即將到期（一格）→ 已到期（空）→ 未計時（空＋斜線）。格數承載意義，灰階與色盲情況下仍可區分。語意刻意採用電量計的日常直覺——**滿＝時間還多、空＝該補擦**，不需要學習。
- **斜線一律代表「停用／不適用」**，目前用在「未計時」與「通知未開啟」。

### 單色／雙色怎麼分

第一判準：**這個圖示會不會被放進按鈕、連結或狀態列？** 會 → 單色，必須繼承外層語意色；只出現在卡片或區塊標題 → 可以雙色。整個 tool 群都是走這條，所以它們一律單色。

第二判準是造型逼出來的：**這個造型有沒有內部面積可以承載第二色？** `feature-locate` 在卡片標題裡，按第一判準可以雙色，但實心導航箭頭是單一實心塊，內部沒有可填的面積——跟閃電同一個問題。要嘛切半（那會把「琥珀金是重點不是結構」的唯一例外變成兩個），要嘛單色。選單色。

所以看到某個 feature 圖示是單色時，先確認是哪一條判準——**不要**倒推成「它一定在按鈕裡」。

## 八、取代 Lucide：現況盤點

**政策：不使用任何第三方圖示素材庫。** 所有圖示都來自本系統，以 inline SVG 進入程式碼。理由是圖示的造型語言直接繼承 Logo 的實心圓點＋膠囊線條，素材庫圖示無法承載這個品牌訊號，混用會讓介面看起來像拼裝的。

**2026-08-29 更新**：**所有缺口的圖示都已繪製並接進元件**。最後 8 處 `@lucide/vue` import 已換成 `<Icon name="..." />` 或專用 loader，依賴也已從 `apps/web/package.json` 移除。README 舊版列的 10 個延後項目裡，`Moon` 與 `MoonStar` 在現行程式碼已經不存在——那份清單是 2026-08-22 的快照，元件後來被移除了，所以實際只需要補 8 個。

**2026-08-22 的舊敘述（保留作為歷史）**：38 個不重複圖示中，**28 個已替換完成**，透過 `apps/web/src/components/icons/Icon.vue` 這個單一進入點消費 `apps/web/src/generated/icons.generated.ts`（由 `generate-icons.mjs` 從 `docs/design/icon-system/icons/` 產生，跟衛教內容、行政區資料同一套「docs/ 是來源、generated/ 是產物」慣例）。`@lucide/vue` 依賴**還不能移除**——剩下 10 個功能型圖示刻意延後（見下方），仍在使用。

## 九、使用規則

- 顏色用 `currentColor`（單色）或既有 token，不在元件內寫死 hex。
- 圖示必須承擔資訊；純裝飾的圖示直接不放。
- 尺寸從 **16／20／24／32** 四個檔位選，不要再發明新數值（舊系統散成 12 種值是明確的反面教材）。角色對照見 `DESIGN.md` 第八節；32 是 2026-08-29 的 B9 裁決 1 新增，同一輪明確**否決**了 B9 規格原本提的 18px。
- 動畫只用 `opacity`，不用位移或縮放。
- **不引入第三方圖示庫。**

## 十、造型概念的取捨紀錄

這幾個決定是實際畫出來、看過之後才收斂的，記下來避免之後重蹈覆轍。

### 倒數四狀態：剩餘量計量表

| 試過的概念               | 為什麼不用                                                               |
| ------------------------ | ------------------------------------------------------------------------ |
| 圓環＋圓餅切片           | 讀起來像圖表，不像時間                                                   |
| 圓形水位填滿             | 兩種中間狀態在 16px 幾乎一樣；且「越滿＝越該補擦」與電量計的日常直覺相反 |
| 沙漏                     | 概念最具體，但沙子多寡的差異在 18px 看不出來，四個狀態長得像同一個圖     |
| 環形進度弧線             | 辨識度不錯，但「即將到期」的短弧看起來像斷掉的碎片                       |
| **剩餘量計量表**（採用） | 四狀態在 18px 差異最大，且滿／空的語意不需要學習                         |

### 通知類：鈴鐺

| 試過的概念       | 為什麼不用                                           |
| ---------------- | ---------------------------------------------------- |
| 放射弧線         | 那是 WiFi／訊號的既有語彙，會被直接誤讀成連線狀態    |
| 角落徽章圓點     | 圓點與方框邊線交疊產生亂線，構圖偏向對角，看起來歪斜 |
| 卡片＋未讀圓點   | 構圖是正的，但太抽象，讀不出「通知」                 |
| **鈴鐺**（採用） | 最直覺的通知符號                                     |

Logo 規格的「不使用警報鈴」寫在**第六節「禁止方向」**，約束對象是品牌標記，不是 UI 狀態圖示（同一份清單也禁止驚嘆號，但警告圖示仍需要它）。三種狀態靠鈴舌區分：

| 狀態               | 造型                 |
| ------------------ | -------------------- |
| 通知設定（已啟用） | 完整鈴鐺＋琥珀金鈴舌 |
| 背景通知尚未完成   | 鈴口斷開一段＋鈴舌   |
| 通知未開啟         | 完整鈴鐺＋鈴舌＋斜線 |

鈴舌的兩次失敗嘗試：**空心鈴舌**——線寬 2.5 畫 r=1.55 的圓，外徑會變成 2.8（實心點只有 1.8），中間的洞只剩 0.3，看起來就是一顆更大的實心點；**不畫鈴舌**——大小不一的問題解決了，但變得跟「通知設定」的完整鈴鐺太接近。最後改由鈴口的缺口承載「尚未完成」，鈴舌一律相同。缺口是用兩段獨立線條畫的，不是虛線，位置完全可控。

結論：**2.5 線寬做不出小尺寸的圓環**，需要「空心」語意時要換其他方式。

### 警告：圓角三角形＋驚嘆號

曾考慮換成圓形，但三角形本身承載「警示」語意，正好滿足「狀態不能只靠顏色判斷」的要求；換成圓形後輪廓會與「已儲存」「標示尚未確認」完全相同，只剩顏色可區分。

驚嘆號貼近三角形邊緣的問題，是靠**圓角三角形**解決的：把尖角切掉之後內部可用寬度變大，驚嘆號左右的間隙從約 0.6 增加到約 1.5。另一個候選方案是「只留一個實心圓點」，雖然最乾淨，但那是靠拿掉辨識度最高的元素來迴避擁擠，警示強度會弱一階。

圓角同時讓它更融入整體——其餘 19 個圖示全是圓端點與圓轉角，三個尖角的三角形原本才是異類。

### 環形箭頭（重新整理／重置）：實心三角，且要指向缺口

畫這兩個時連續踩了兩個坑，都跟「箭頭前方有什麼」有關。

| 試過的做法                         | 為什麼不行                                                                                                 |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 描邊 V 型箭頭，開口朝後            | 在直線箭頭上沒問題，但在弧線上，V 的其中一臂幾乎與弧線相切**平行**，變成兩條並行的線，讀起來像觸角不像箭頭 |
| 改成實心三角，但箭頭指向弧線本體   | 三角尖端落在弧線的筆畫寬度之內（線寬 2.5，尖端只離弧線 1.2），整個被吞掉變成一顆小瘤                       |
| **實心三角＋箭頭指向缺口**（採用） | 前方淨空，三角完整露出來，18px 仍讀得出方向                                                                |

關鍵是**弧線的終點要落在缺口前緣**，讓箭頭朝著空白處指。做法是把弧線畫成 280°（缺口 80°），起點在右側中段、終點在正上方，三角形接在正上方的終點往右指——右上方正好是缺口。`reset` 是同一個造型水平鏡射。

實心三角與其他工具型圖示的描邊 V 型不一致，是刻意的取捨：直線箭頭的 V 型讀得清楚就不必改，環形箭頭則非改不可。系統本來就有實心＋描邊混用的先例（沙漏的沙、山景的太陽）。

### 匯出：容器＋箭頭向外，不是向下箭頭

第一版畫成「向下箭頭＋底線」，也就是通用的下載圖示。兩個問題：

1. **語意錯了。** 向下箭頭是「從外面下載進來」，但這裡是把自己的本機資料倒出成檔案，方向相反。
2. **跟 `more-install` 撞剪影。** 安裝到主畫面已經是「托盤＋向下箭頭」，兩個放在一起分不出來。

改成開口朝右的方框加一支穿出去的箭頭，方向與語意一致，也跟 `more-install` 完全分開。

**注意**：這個造型也是常見的「登出」圖示。之後若要做 Google 帳號登出，不能直接沿用這一個，得另外設計。

### UV 五級：格數圖示（已拿掉）

最早比照倒數四狀態，畫了 5 個漸進填滿格數的圖示（`state-uv-low` 到 `state-uv-extreme`）。後來核對實際會用到 UV 等級的地方——`FiveDayUvCard.vue`——發現它已經同時顯示指數數字（如「11」）與風險等級文字（如「危險級」），數字本身就不靠顏色也能區分，格數圖示只是把同一件事再講一次。「狀態必須同時有色彩、圖示與文字」這條規則要防的是沒有裸數字可看的狀態，UV 預報不屬於這種情況。5 個檔案與陣列項目都已移除。

### 2026-08-29 這批的三個撞剪影風險

新畫的 12 個都先跟既有 50 個對照過剪影，有三處必須處理：

| 風險                                                          | 處理                                                                                                                                                                                         |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **搜尋 vs `education-uv-basics`**                             | `education-uv-basics`（了解今天的 UV）**已經是放大鏡＋琥珀金核心**。再畫一個放大鏡當搜尋，兩者在 18px 只差顏色。**決定不畫搜尋**——目前程式碼也沒有搜尋功能，等真的要做時再想一個不撞的造型。 |
| **`feature-uv-forecast` vs `state-online` / `state-offline`** | 初版畫成雲＋太陽，跟那兩個狀態圖示是同一朵雲，靠一顆琥珀金點區隔，20px 撐不住。已改成純太陽，完全離開雲家族（見下方取捨紀錄）。                                                              |
| **`feature-session-product` vs `gear-sunscreen`**             | 初版畫成「瓶＋勾」，跟 `gear-sunscreen` 同一個瓶身家族，16px 只差一個勾，風險太高。改成吊牌之後剪影完全分開（見下方取捨紀錄）。                                                              |

### 收藏：書籤，不是星星

星星有五個尖角，跟第一節「不使用尖角」直接衝突；`state-warning` 為了留住三角形的警示語意都得改成圓角三角形，沒有理由為「收藏」再引進五個尖角。書籤是同樣通用的收藏符號，全部由圓轉角構成，而且跟系統裡任何造型都不撞。

### 調整要提醒的部位：不畫新圖示，沿用 `tool-edit`

原本規劃了一個 `feature-adjust`（兩軌滑桿），2026-08-29 **刪掉**，改用既有的 `tool-edit`。

滑桿有兩個問題：它是 Lucide `SlidersHorizontal` 的造型；而且**滑桿代表連續數值**，但這個按鈕（`QuickProtectionSummary` 的「調整要提醒的部位」）實際做的是從清單裡勾選部位，不是拉數值。語意本來就偏了。

比過的候選：

| 候選                         | 為什麼不用                                                                                                    |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 清單＋勾                     | 最貼近實際操作，但跟 `feature-setup-steps` 內部的橫線只差一個外框——而它在按鈕裡是單色，沒有琥珀金可以拿來區隔 |
| 勾選框                       | 語意偏向「已完成／已確認」，跟「去挑選」差一格                                                                |
| 人形＋部位標記               | 24 格畫人形在 16px 撐不住，而這個圖示只用在 16px                                                              |
| **沿用 `tool-edit`**（採用） | 「調整要提醒的部位」＝編輯這組選擇，鉛筆對得上，而且**讓系統少一個圖示**                                      |

**這是這批唯一一個「決定不畫」的結論，值得單獨記一筆。** 系統的價值來自克制而不是數量——少一份幾何要維護，也少一個撞剪影的風險。之後遇到新的圖示需求時，先問「有沒有既有的可以用」，再問「要畫成什麼樣子」。

### 五日 UV 預報：太陽，不是雲

初版畫成「雲＋左上一顆琥珀金太陽」，沿用 `state-online` 那朵雲的幾何。兩個問題都是硬傷：

**一、剪影會跟離線狀態同框。** `GlobalStatusBanner` 掛在 `AppShell.vue` 裡，**每一頁都會出現**，`/forecast` 也不例外。離線時畫面上會同時有兩朵一模一樣的雲——一朵在頁面標題旁（預報）、一朵在狀態橫幅（離線）。靠一顆琥珀金點區隔，在 20px 只是一顆點，撐不住。

**二、語意根本是錯的。** `ForecastPage` 的副標寫「依你設定的地區顯示未來五天的**紫外線指數**」。雲講的是天氣，不是紫外線；更糟的是它有反向暗示——多雲讀起來像「紫外線弱」，但多雲仍可能是高 UV。

改成太陽之後兩個問題一起解決，而且太陽本來就是 Logo 的造型 DNA（06 播報印記＝實心圓點＋膠囊射線）。

**三個必須照做的細節**：

1. **圓盤要實心，不能畫成圓環。** `education-uv-basics`（了解今天的 UV）是「圓環＋琥珀金實心核心＋把手」，太陽若也是圓環＋核心，兩者在 16px 就只差一根把手。實心琥珀金圓盤 vs 空心環包一顆點，量體完全不同。
2. **射線是 6 道，不是 8 道。** 三個數量都渲染過：8 道在 16px 相鄰間隙只剩約 1.1px，抗鋸齒一糊就變成毛球；4 道在 16px 讀成「＋」，撞準心語彙；6 道間隙約 3.8px，16px 仍數得出來。系統最小的尺寸是 16px，所以要為小尺寸最佳化，不是為預覽板的大圖。（2026-08-29 新增 32 檔位之後，這個結論不變——小尺寸讀得出來的，放大一定也讀得出來，反過來不成立。）
3. **射線要對稱。** Logo 的射線是**單側非對稱**（播報感）。這裡畫成對稱六向，才不會讓人覺得「App 的 logo 怎麼跑到卡片標題裡」。

**這是唯一一個琥珀金落在畫布中央而不是上半部的圖示**，因為太陽的核心就在中心。圓心已經上移到 y=11.8 略作補償，但這條規則在這裡確實只是擦邊——記在這裡，不要拿它當先例。

### 取得目前位置：實心導航箭頭

原本是準心（十字＋圓環＋中心點），也就是 Lucide `LocateFixed` 的造型。兩個問題：**它就是那個素材庫的圖**，而這套系統存在的理由正是「不要看起來像拼裝的」；而且「圓環＋中心點」跟 `state-unverified`、`state-success`、`education-uv-basics` 同屬圓形家族，16px 全靠那四根小刺區分。

| 候選                       | 為什麼不用                                                                                                                         |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 準心（原本的）             | 是 Lucide 的造型，且落在已經很擁擠的圓形家族裡                                                                                     |
| 漣漪（中心點＋兩圈同心弧） | 語意最直白，但兩圈弧在 16px 會併成一坨。（「放射弧線是 WiFi 語彙」那條記在通知圖示那節，在**定位**這裡訊號語彙反而是對的，不適用） |
| 地標＋地面投影橢圓         | 直接撞 `feature-region`，而這兩個圖示會**出現在同一頁**（`/region` 的「目前設定」與「裝置定位」）                                  |
| 指南針                     | 講的是「方向」不是「我在哪裡」，語意偏一格；而且又回到圓形家族                                                                     |
| **實心導航箭頭**（採用）   | 系統裡沒有任何孤立的實心三角，剪影獨一無二，16px 最穩                                                                              |

實心三角在系統裡不是外來語彙——`tool-refresh`／`tool-reset` 的箭頭就是實心三角而不是描邊 V 型，理由記在本節前面。做法跟閃電一樣：`fill` ＋同色 `stroke`（`stroke-linejoin="round"`），用同色描邊把尖端磨圓，才不違反「不使用尖角」。

尾端要**凹得夠深**（現為約 5.0），否則描邊的圓角會把凹口填平，變成一個等腰三角，讀起來就從「導航」變成「播放」。

### 本次使用的防曬乳：吊牌，而且先改對了 brief

這個圖示改過兩次，第一次是**照著錯的 brief 畫的**——沿用 Lucide 的名字 `PackageCheck`，理解成「產品快照已確認」，畫成瓶身＋勾。後來讀 `ProductSnapshotEditor.vue` 的實際文案才發現：

> **本次使用** — 只用在這次提醒
> 只會記錄這次提醒需要的包裝標示，不會新增到你的防曬乳清單。

**這是區塊標題，不是「已確認」狀態。** 卡片在講兩件事：只用在這一次（不進清單）、以及從包裝標示抄下來的資料（間隔、耐水）。名字錯了，畫出來的東西自然也對不上。

改名為 `feature-session-product`、搬到 feature 群之後，它就不必是單色，可以帶琥珀金重點。

造型候選比過四個：

| 候選                 | 為什麼不用                                                                                                  |
| -------------------- | ----------------------------------------------------------------------------------------------------------- |
| 瓶身＋琥珀金標籤     | 語意最準，但跟 `gear-sunscreen` 同一個瓶身輪廓，16px 只差琥珀金的位置（瓶蓋 vs 瓶身中段），分不出來         |
| 相機（「快照」直譯） | 雙色最好做，16px 也穩。但 App 沒有拍照功能，畫相機等於做出「按這裡可以拍包裝」的功能承諾，點下去卻是表單    |
| 便利貼（摺角紙片）   | 「臨時記一張」的語意很貼，但跟 `feature-setup-steps` 都是「圓角矩形＋內部橫線」，而且兩者都在設定流程裡出現 |
| **吊牌**（採用）     | 剪影跟系統裡任何造型都不撞，16px 最穩，而且「標籤」正好對應「包裝標示」                                     |

**注意兩件事**：

1. 吊牌的穿繩孔畫成**實心琥珀金圓點**（r=1.9），不是空心圓環。README 第十節前面已經記過「2.5 線寬做不出小尺寸的圓環」，這裡直接套用那個結論。
2. **不要把吊牌畫成直立、頂端收尖的形狀**——那會變成房子，直接撞 `context-indoor`。現在的版本是斜置的，角塊在左上、尖端指右下。

### 快速防護摘要：閃電，而且是系統唯一的實心雙色圖示

第一版畫的是閃亮星星（沿用原本 Lucide 的 `Sparkles`），2026-08-29 換掉。

**為什麼不是星星**：星星在介面裡講的是「魔法／自動生成」，那是 AI 產品的通用語彙。但這張卡片的 preset 實際上是「一組已經幫你選好的身體部位」（見 `setupCatalog.ts` 的 `label`／`summary`），跟「自動生成」沒有關係。

**為什麼不是盾牌**：盾牌是防護的通用符號，剪影也乾淨，但 `DESIGN.md` 第 483 行明訂**不使用綠色暗示「安全」或「防護有效」——防曬沒有「完成」狀態**。那條規則要防的是語意，不只是顏色；盾牌傳達的正是「你已受保護」，所以排除。

**為什麼是實心切半，不是描邊**：閃電在 24 格內用 2.5 線寬描邊之後，肢體寬度只剩約 2.8，扣掉兩側各 1.25 的筆畫，內部可填的面積不到 0.4——琥珀金填進去在 36px 以下就完全看不見。四個版本都渲染出來比過：

| 版本                                       | 結果                                           |
| ------------------------------------------ | ---------------------------------------------- |
| 描邊空心＋填上肢                           | 琥珀金只剩一條細縫，36px 以下消失              |
| 描邊空心單色                               | 造型與其他圖示一致，但完全失去重點色           |
| 實心墨咖＋左上琥珀金速度線                 | 速度線讀成獨立的橫條，16px 與閃電本體糊在一起  |
| **實心切半：上肢琥珀金、下肢墨咖**（採用） | 四個尺寸都讀得出，琥珀金有實際量體且落在上半部 |

**這是「琥珀金是重點，不是結構」的唯一例外**，而且是刻意的：閃電這個造型沒辦法用描邊承載第二色，要嘛放棄重點色、要嘛讓它承擔一半的形。使用者選了後者。若之後有其他圖示想比照辦理，**先確認它真的無法用描邊＋填色達成**——這個例外的成立條件是造型限制，不是偏好。

實作上兩塊都是 `fill` ＋同色 `stroke`（`stroke-linejoin="round"`），用同色描邊把實心形狀的尖角磨圓，才不違反「不使用尖角」。琥珀金那塊畫在下層，且沿接縫往墨咖那側多伸出約 0.4，避免兩塊之間出現奶油色髮絲縫。

### 編輯與刪除：上方留白是靠縮短造型換來的，不是靠位移

兩個圖示原本的視覺重心都偏上，看起來像貼著上緣。修的時候發現**兩個要用不同做法**：

- **鉛筆**只靠位移不夠——它下緣本來就只剩 2.45 的留白。最後是整支等比縮到 0.88 再往下放，上方留白從 3.35 拉到 5.45。
- **垃圾桶**完全不能用位移，它下緣只有 2.15。做法是把提把與桶蓋往下移、桶底維持原位，等於**桶身縮短約 1.9**。上方留白從 2.35 變成 4.35，代價是垃圾桶比初版矮一截——這是使用者確認可以接受的取捨。

通則：**24 格裡要多出上方留白，幾乎一定得縮短造型**，因為下緣通常也已經貼近安全邊界。先量兩端的留白再決定要位移還是要縮放，不要預設可以整個搬。

### 分享：線要接進圓點，圓點要夠大

三點連線的三個版本，兩次都是為了同一件事在調——**跟 `tool-chevron-right` 分開**：

| 版本                                      | 問題                                                                                                                                                                             |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 線與圓點留 1.0 淨空                       | 18px 下線與點糊成一體，讀成「<」，直接撞 chevron                                                                                                                                 |
| 線縮短、跟圓點完全分離                    | 小尺寸不糊了，但 96px 下看起來就是「三個點旁邊放了兩條線」，沒有連接關係，讀不出「分享到別處」                                                                                   |
| **線接到圓心、圓點放大到 r=2.75**（採用） | 線畫在下層、端點直接落在圓心，圓點蓋上去，接合處完全沒有縫。圓點放大之後，小尺寸的視覺重心在「三個節點」而不是「兩條筆畫」——chevron 是等寬筆畫加一個尖頂點，兩者在 16px 仍分得開 |

圓點半徑試過 2.3／2.75／3.1：2.3 在 16px 節點太弱、又變回 chevron；3.1 的圓點把線吞掉，變成一坨。2.75 是兩邊都成立的唯一值。

這也剛好回到 Logo 的造型 DNA——**膠囊線條從實心圓點長出去**，本來就該是接在一起的。

### 分享：三點連線，不是向外箭頭

第一直覺是「方框＋向外箭頭」，但那正好是 `tool-download`（匯出）的造型——第十節前面已經記過，匯出改成這個造型就是為了跟 `more-install` 分開，不能再讓分享來撞它。三點連線是另一個同樣通用的分享語彙，而且用的是系統已有的「實心圓點＋線條」DNA。

### 登出：電源符號，不是向外箭頭

**與分享同一個坑，第二次。** 登出最通用的符號就是「方框＋往外射出的箭頭」——但那個幾何在這個 repo 已經是 `tool-download`（匯出）。而且這次更不能撞：兩者會出現在**相鄰的設定頁**，資料設定頁的「匯出本機資料」與帳號頁的「登出」，同一個圖形在兩頁代表兩件事。

改用電源符號（開口朝上的圓弧＋垂直膠囊線）。三個理由：

1. **造型 DNA 直接吻合**——圓弧與垂直線都是 round 端點的膠囊線條，不需要引入新的造型元素（人像剪影就會，這個系統目前沒有任何人形）
2. **與匯出在所有尺寸都分得開**——96／36／24／18 四級並排比對過
3. 電源符號在主流圖示庫（Material 的 `power_settings_new`）本來就是登出的常見表達，不是自創語彙

幾何：圓心 (12, 13.8)、半徑 5.8、開口半角 40°；垂直線 `M12 5.2V12`，末端落在圓內 1.8，不會從開口穿出去。整體量體 14.1×16.9，與 `tool-download`（約 14×14）同一個級距。

**這一顆沒有 Illustrator 來源檔。** 全域規則是「幾何的真實來源是 Illustrator」，這顆是直接寫 SVG 的例外——要改造型的話，請在 Illustrator 重畫並覆蓋 `icons/tool-sign-out.svg`，之後就回到正常流程。守門在 `apps/web/src/components/icons/signOutIcon.test.ts`，其中一條專門釘住「不可與匯出共用路徑」。

### 調整設定：兩軌，不是三軌

Lucide 的 `SlidersHorizontal` 是三軌。三條 2.5 寬的線塞進 24 格，行距只剩約 3.4，在 18px 會糊成一塊。改成兩軌之後行距 6.8，滑鈕（實心點 r=2.4）也放得下。**軌數不是資訊**，滑桿的語意由「線＋點」承載，減一條不損失任何東西。

### 更多：2×2 網格

原本是水平三點，但量測是 17.5×4.5，與另外兩個導覽圖示（約 13×19）差距太大，放在一起不像同一組。改為 2×2 網格後是 14.1×14.1，量體相當；語意上也剛好對應「更多」頁本身就是卡片網格。

### 提醒：沙漏

原本用「圓環＋中心實心點」，但那與狀態類的圓環家族太接近，也不具體指向這一頁的內容。改用沙漏：直接對應提醒頁的核心（補擦倒數），且與裝備（瓶身）、更多（三點）在輪廓上完全不同。

### 琥珀金的兩條使用規則

1. **琥珀金一律出現在上半部**：瓶蓋、2×2 網格的右上點、沙漏上層的沙、資料庫中間帶、下載箭頭、資訊點都在上半部。唯一的例外是鈴舌，因為鈴舌天生就在鈴鐺底部。
2. **琥珀金是重點，不是結構**：衛教是墨咖書本＋琥珀金書脊；資料庫是墨咖圓柱＋琥珀金中間帶。早期版本讓資料庫的頂部橢圓直接是琥珀金，等於讓重點色承擔結構，量體明顯比其他圖示重。
3. **琥珀金畫在下層**：先畫琥珀金、再畫墨咖結構，讓重點色在交會處收進結構底下，而不是蓋在上面截斷它。沙漏的沙、書脊、資料庫中間帶都照這個順序。

## 十一、兩個渲染陷阱

實作時踩過、值得記下來：

**虛線已完全從系統移除**，因為它同時有三個問題：

1. **圓端點會吃掉間隙**。`stroke-linecap="round"` 讓每段虛線兩端各延伸線寬的一半（1.25），間隙 2.6 會被完全填滿，虛線渲染成實線。
2. **加大間隙又會斷成一顆顆**，看不出是同一條線。
3. **封閉曲線上的虛線會讓造型歪斜**。虛線相位決定斷點落在哪，封閉路徑上無法控制，量測顯示會造成單邊墨跡缺口（實測 x 偏移 0.95）。

需要表達「不啟用／未完成」時，改用斜線（可控、對稱）或明確畫出的缺口（如鈴口斷開，用兩段獨立線條而非虛線）。

另外，**外框置中不等於視覺置中**。20 個圖示的外框中心都準確落在 (12,12)，但三角形、書本、對話框這類量體偏底部的造型仍會看起來下沉，需要靠 `nudgeY` 校正。校正值來自把 SVG 點陣化後量測實際墨跡邊界，不是目測。
