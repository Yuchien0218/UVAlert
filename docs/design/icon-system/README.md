# UVAlert 圖示系統

## 工作流程

**幾何的真實來源是 Illustrator，不是程式碼。**

1. 在 Illustrator 畫圖示，畫布 24×24，匯出成 SVG 到 `icons/<id>.svg`。檔名必須對應 [`generate-icons.mjs`](../../../tools/icon-system/generate-icons.mjs) 的 `ICONS` 登記表裡的 `id`。
2. 跑一次建置腳本：

   ```bash
   node tools/icon-system/generate-icons.mjs
   ```

3. 腳本會就地正規化 `icons/*.svg`，並重新產生兩張預覽板。

### 腳本做什麼、不做什麼

**做**：把 Illustrator 匯出的格式改成可以直接 inline 進 Vue 的樣子——

- `#000`（以及 `#33291F`、`#2E2925`）換成 `currentColor`
- `<defs><style>` 裡的 CSS class 內聯到元素上，然後移除 defs 與 class 屬性
- 注入 `<title>`（中文標籤）、`data-icon`、`data-tone`、`role="img"`
- 統一強調色大小寫為 `#C1832E`、去掉 `stroke-width` 的 `px` 單位

**不做**：不碰幾何。路徑資料原封不動，腳本沒有能力也不應該改造型。

腳本是冪等的，重複執行結果相同，可以安全地隨時再跑。

### 為什麼要正規化

三個問題都會在 App 裡出事，而且都不是潔癖：

| Illustrator 匯出                  | 為什麼不能直接用                                                                                                                          |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `stroke: #000`                    | 設計系統要求墨色用 `currentColor`。寫死黑色的話狀態圖示無法繼承語意色，放在深色倒數面板上會變成看不見的黑塊。而且 `#000` 也不是系統墨色。 |
| `.cls-1` / `.cls-2` 放在 `<defs>` | 每個檔案都從 `.cls-1` 開始編號。同一頁 inline 兩個圖示時 class 會互相覆蓋，這是最難查的那種 bug。                                         |
| 沒有 `<title>`                    | 螢幕閱讀器讀不出圖示語意。                                                                                                                |

> **歷史**：2026-08-19 之前這支腳本是用 JS 函式產生路徑的，結果是「跑一次就把手繪成果整批蓋掉」，差一點真的發生。幾何歸 Illustrator 之後就沒有這個風險——腳本只讀檔、正規化、寫回。

## 一、造型語言

圖示的視覺 DNA 來自 06 播報印記 Logo：**實心圓點＋膠囊狀線條**。

- 畫布 24×24，四周保留約 2px 光學留白。
- 線條寬度固定 `2.5`，端點與轉角一律 `round`——渲染出來就是膠囊形，呼應 Logo 的射線。
- 需要強調的元素用實心填色，不用加粗線條來製造層級。
- 不使用尖角、不使用陰影、不使用漸層。

**UV 五級不畫圖示。** `FiveDayUvCard.vue` 已經同時顯示指數數字（如「11」）與風險等級文字（如「危險級」），數字本身就是不靠顏色也能區分的資訊，不需要額外的格數圖示重複同一件事。這條規則真正要防的是「沒有裸數字可看」的狀態（倒數四狀態），所以格數計量表只留給那裡。原本畫好的 5 個 `state-uv-*` 已從登記表與 `icons/` 移除，取捨原因見第十節。

### 為什麼狀態類不用琥珀金

倒數狀態在 `packages/ui/src/styles.css` 裡各有語意色（`--color-tracking` 藍、`--color-soon` 琥珀、`--color-due` 紅）。狀態圖示若寫死琥珀金會與語意色衝突。單色 `currentColor` 讓圖示自動繼承外層語意色，一份幾何走遍所有狀態。工具型圖示是同樣的道理——它們會出現在按鈕、連結、狀態列等各種語意情境裡。

## 三、不依賴顏色的區分方式

`docs/design/current-direction.md` 明訂「狀態必須同時有色彩、圖示與文字」。因此：

- **倒數／部位四狀態**用剩餘量計量表：追蹤中（三格）→ 即將到期（一格）→ 已到期（空）→ 未計時（空＋斜線）。格數承載意義，灰階與色盲情況下仍可區分。語意刻意採用電量計的日常直覺——**滿＝時間還多、空＝該補擦**，不需要學習。
- **斜線一律代表「停用／不適用」**，目前用在「未計時」與「通知未開啟」。

## 八、取代 Lucide：現況盤點

**政策：不使用任何第三方圖示素材庫。** 所有圖示都來自本系統，以 inline SVG 進入程式碼。理由是圖示的造型語言直接繼承 Logo 的實心圓點＋膠囊線條，素材庫圖示無法承載這個品牌訊號，混用會讓介面看起來像拼裝的。

**2026-08-22 更新**：38 個不重複圖示中，**28 個已替換完成**，透過 `apps/web/src/components/icons/Icon.vue` 這個單一進入點消費 `apps/web/src/generated/icons.generated.ts`（由 `generate-icons.mjs` 從 `docs/design/icon-system/icons/` 產生，跟衛教內容、行政區資料同一套「docs/ 是來源、generated/ 是產物」慣例）。`@lucide/vue` 依賴**還不能移除**——剩下 10 個功能型圖示刻意延後（見下方），仍在使用。

## 九、使用規則

- 顏色用 `currentColor`（單色）或既有 token，不在元件內寫死 hex。
- 圖示必須承擔資訊；純裝飾的圖示直接不放。
- 尺寸從 16／20／24 三個檔位選，不要再發明新數值（舊系統散成 12 種值是明確的反面教材）。
- 動畫只用 `opacity`，不用位移或縮放。
- **不引入第三方圖示庫。**

## 十、造型概念的取捨紀錄

這幾個決定是實際畫出來、看過之後才收斂的，記下來避免之後重蹈覆轍。

### 倒數四狀態：剩餘量計量表

| 試過的概念               | 為什麼不用                                                               |
| ------------------------ | ------------------------------------------------------------------------ |
| 圓環＋圓餅切片           | 讀起來像圖表，不像時間                                                   |
| 圓形水位填滿             | 兩種中間狀態在 16px 幾乎一樣；且「越滿＝越該補擦」與電量計的日常直覺相反 |
| 沙漏                     | 概念最具體，但沙子多寡的差異在 18px 看不出來，四個狀態長得像同一個圖     |
| 環形進度弧線             | 辨識度不錯，但「即將到期」的短弧看起來像斷掉的碎片                       |
| **剩餘量計量表**（採用） | 四狀態在 18px 差異最大，且滿／空的語意不需要學習                         |

### 通知類：鈴鐺

| 試過的概念       | 為什麼不用                                           |
| ---------------- | ---------------------------------------------------- |
| 放射弧線         | 那是 WiFi／訊號的既有語彙，會被直接誤讀成連線狀態    |
| 角落徽章圓點     | 圓點與方框邊線交疊產生亂線，構圖偏向對角，看起來歪斜 |
| 卡片＋未讀圓點   | 構圖是正的，但太抽象，讀不出「通知」                 |
| **鈴鐺**（採用） | 最直覺的通知符號                                     |

Logo 規格的「不使用警報鈴」寫在**第六節「禁止方向」**，約束對象是品牌標記，不是 UI 狀態圖示（同一份清單也禁止驚嘆號，但警告圖示仍需要它）。三種狀態靠鈴舌區分：

| 狀態               | 造型                 |
| ------------------ | -------------------- |
| 通知設定（已啟用） | 完整鈴鐺＋琥珀金鈴舌 |
| 背景通知尚未完成   | 鈴口斷開一段＋鈴舌   |
| 通知未開啟         | 完整鈴鐺＋鈴舌＋斜線 |

鈴舌的兩次失敗嘗試：**空心鈴舌**——線寬 2.5 畫 r=1.55 的圓，外徑會變成 2.8（實心點只有 1.8），中間的洞只剩 0.3，看起來就是一顆更大的實心點；**不畫鈴舌**——大小不一的問題解決了，但變得跟「通知設定」的完整鈴鐺太接近。最後改由鈴口的缺口承載「尚未完成」，鈴舌一律相同。缺口是用兩段獨立線條畫的，不是虛線，位置完全可控。

結論：**2.5 線寬做不出小尺寸的圓環**，需要「空心」語意時要換其他方式。

### 警告：圓角三角形＋驚嘆號

曾考慮換成圓形，但三角形本身承載「警示」語意，正好滿足「狀態不能只靠顏色判斷」的要求；換成圓形後輪廓會與「已儲存」「標示尚未確認」完全相同，只剩顏色可區分。

驚嘆號貼近三角形邊緣的問題，是靠**圓角三角形**解決的：把尖角切掉之後內部可用寬度變大，驚嘆號左右的間隙從約 0.6 增加到約 1.5。另一個候選方案是「只留一個實心圓點」，雖然最乾淨，但那是靠拿掉辨識度最高的元素來迴避擁擠，警示強度會弱一階。

圓角同時讓它更融入整體——其餘 19 個圖示全是圓端點與圓轉角，三個尖角的三角形原本才是異類。

### 環形箭頭（重新整理／重置）：實心三角，且要指向缺口

畫這兩個時連續踩了兩個坑，都跟「箭頭前方有什麼」有關。

| 試過的做法                         | 為什麼不行                                                                                                 |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 描邊 V 型箭頭，開口朝後            | 在直線箭頭上沒問題，但在弧線上，V 的其中一臂幾乎與弧線相切**平行**，變成兩條並行的線，讀起來像觸角不像箭頭 |
| 改成實心三角，但箭頭指向弧線本體   | 三角尖端落在弧線的筆畫寬度之內（線寬 2.5，尖端只離弧線 1.2），整個被吞掉變成一顆小瘤                       |
| **實心三角＋箭頭指向缺口**（採用） | 前方淨空，三角完整露出來，18px 仍讀得出方向                                                                |

關鍵是**弧線的終點要落在缺口前緣**，讓箭頭朝著空白處指。做法是把弧線畫成 280°（缺口 80°），起點在右側中段、終點在正上方，三角形接在正上方的終點往右指——右上方正好是缺口。`reset` 是同一個造型水平鏡射。

實心三角與其他工具型圖示的描邊 V 型不一致，是刻意的取捨：直線箭頭的 V 型讀得清楚就不必改，環形箭頭則非改不可。系統本來就有實心＋描邊混用的先例（沙漏的沙、山景的太陽）。

### 匯出：容器＋箭頭向外，不是向下箭頭

第一版畫成「向下箭頭＋底線」，也就是通用的下載圖示。兩個問題：

1. **語意錯了。** 向下箭頭是「從外面下載進來」，但這裡是把自己的本機資料倒出成檔案，方向相反。
2. **跟 `more-install` 撞剪影。** 安裝到主畫面已經是「托盤＋向下箭頭」，兩個放在一起分不出來。

改成開口朝右的方框加一支穿出去的箭頭，方向與語意一致，也跟 `more-install` 完全分開。

**注意**：這個造型也是常見的「登出」圖示。之後若要做 Google 帳號登出，不能直接沿用這一個，得另外設計。

### UV 五級：格數圖示（已拿掉）

最早比照倒數四狀態，畫了 5 個漸進填滿格數的圖示（`state-uv-low` 到 `state-uv-extreme`）。後來核對實際會用到 UV 等級的地方——`FiveDayUvCard.vue`——發現它已經同時顯示指數數字（如「11」）與風險等級文字（如「危險級」），數字本身就不靠顏色也能區分，格數圖示只是把同一件事再講一次。「狀態必須同時有色彩、圖示與文字」這條規則要防的是沒有裸數字可看的狀態，UV 預報不屬於這種情況。5 個檔案與陣列項目都已移除。

### 更多：2×2 網格

原本是水平三點，但量測是 17.5×4.5，與另外兩個導覽圖示（約 13×19）差距太大，放在一起不像同一組。改為 2×2 網格後是 14.1×14.1，量體相當；語意上也剛好對應「更多」頁本身就是卡片網格。

### 提醒：沙漏

原本用「圓環＋中心實心點」，但那與狀態類的圓環家族太接近，也不具體指向這一頁的內容。改用沙漏：直接對應提醒頁的核心（補擦倒數），且與裝備（瓶身）、更多（三點）在輪廓上完全不同。

### 琥珀金的兩條使用規則

1. **琥珀金一律出現在上半部**：瓶蓋、2×2 網格的右上點、沙漏上層的沙、資料庫中間帶、下載箭頭、資訊點都在上半部。唯一的例外是鈴舌，因為鈴舌天生就在鈴鐺底部。
2. **琥珀金是重點，不是結構**：衛教是墨咖書本＋琥珀金書脊；資料庫是墨咖圓柱＋琥珀金中間帶。早期版本讓資料庫的頂部橢圓直接是琥珀金，等於讓重點色承擔結構，量體明顯比其他圖示重。
3. **琥珀金畫在下層**：先畫琥珀金、再畫墨咖結構，讓重點色在交會處收進結構底下，而不是蓋在上面截斷它。沙漏的沙、書脊、資料庫中間帶都照這個順序。

## 十一、兩個渲染陷阱

實作時踩過、值得記下來：

**虛線已完全從系統移除**，因為它同時有三個問題：

1. **圓端點會吃掉間隙**。`stroke-linecap="round"` 讓每段虛線兩端各延伸線寬的一半（1.25），間隙 2.6 會被完全填滿，虛線渲染成實線。
2. **加大間隙又會斷成一顆顆**，看不出是同一條線。
3. **封閉曲線上的虛線會讓造型歪斜**。虛線相位決定斷點落在哪，封閉路徑上無法控制，量測顯示會造成單邊墨跡缺口（實測 x 偏移 0.95）。

需要表達「不啟用／未完成」時，改用斜線（可控、對稱）或明確畫出的缺口（如鈴口斷開，用兩段獨立線條而非虛線）。

另外，**外框置中不等於視覺置中**。20 個圖示的外框中心都準確落在 (12,12)，但三角形、書本、對話框這類量體偏底部的造型仍會看起來下沉，需要靠 `nudgeY` 校正。校正值來自把 SVG 點陣化後量測實際墨跡邊界，不是目測。
