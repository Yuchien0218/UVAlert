# S-04 揭露層次實施計畫

**目標**：從 20 個常駐可見單選鈕改為 0-2-3 的三層揭露

**預計工作量**：12 小時

---

## 一、現況分析

### 問題
- 常駐可見單選鈕：20 個
- 需要捲動：3 屏
- 違反規格：PRD §5.2 第 5 點的層級規定

### 根本原因
實作沒有照規格分層，不是選項多餘。

---

## 二、規格要求

### 三層揭露層次

| 層次 | 內容 | 常駐可見單選鈕 | 狀態 |
| --- | --- | --- | --- |
| 1️⃣ 收合（預設） | 每個部位群組一行：群組名稱 + 目前方法的狀態文字 | **0 個** | 關閉 |
| 2️⃣ 點開一組 | 兩個主要選項 + `其他情況` 文字連結 | **2 個** | 展開 |
| 3️⃣ 展開「其他情況」 | 才出現第三個選項 | **3 個** | 全展開 |

### 操作規則

1. **預設收合** ✓
   - 每個群組顯示為一行：群組名稱 + 狀態文字
   - 不得有任何可見單選鈕

2. **一次只展開一個群組** ✓
   - 打開 A 群組時，自動收起 B 群組
   - 或允許同時展開多個（更彈性）

3. **選「已擦防曬產品」後直接收合** ✓
   - 選中主選項立即收起該群組
   - 更新狀態文字為「已擦防曬產品」

4. **選「被衣物完整遮住」後不立即收合** ✓
   - 顯示選填追問：「衣物下方也有擦防曬產品嗎？」
   - 用戶按「完成」收起

5. **「衣物下方也有擦防曬」改為選後追問** ✓
   - 不放在第一層並列
   - 只在選「衣物覆蓋」後才呈現

6. **「其他外用產品」改為「其他情況」後出現** ✓
   - 點「其他情況」文字連結展開第三層
   - 才出現「其他外用產品」單選鈕

7. **衣物覆蓋狀態文字不使用 untimed 紫色** ✓
   - 衣物覆蓋是中性正常狀態
   - 使用次要文字色（灰色）

## 三、UI 元件設計


```
┌─ [▼] 臉部（Face）
│  這次實際補擦哪些部位？
│
│  ○ 已擦防曬產品
│  ○ 被衣物完整遮住
│  ⚙ 其他情況
│
```

**顯示內容**

**點擊行為**
- 選主選項 → 更新狀態 → 自動收合

### 3.3 衣物覆蓋追問（選「衣物覆蓋」後）


**點擊行為**

```
│  ○ 已擦防曬產品

│    ○ 衣物下方也有擦防曬

│  
│  [完成]
```

**顯示條件**
- 點「其他情況」連結後展開

**點擊行為**
- 用戶選擇 → 點「完成」收合

## 四、狀態機管理

### 群組狀態

```typescript
interface GroupState {
  groupId: string;
  isExpanded: boolean;           // 是否展開
  selectedMethod: Method | null; // 選中的方法
  showClothingFollowUp: boolean; // 衣物追問是否展開
  showOtherOptions: boolean;     // 其他情況是否展開
}
```

### 方法轉換邏輯

```
未設定
  ↓ (選主選項)
主選項選中 → 自動收合
  ↓ (衣物選項特殊處理)
衣物選中 → 顯示追問 → 用戶完成 → 收合
  ↓ (點「其他情況」)
展開追問 → 用戶選擇 → 點「完成」 → 收合
```

## 十、決策點

### 開放性設計問題

1. **是否一次只展開一個群組？**
   - 選項 A（推薦）：一次只展開一個，打開新的自動收起舊的
   - 選項 B：允許同時展開多個
   - **決定**：選項 A（更符合規格的「一次只展開一組」說法）

2. **衣物下方選項的標籤位置？**
   - 選項 A（規格）：選「衣物」後下方出現
   - 選項 B：在「其他情況」層級
   - **決定**：選項 A（符合規格要求）

3. **「其他情況」應該是展開/收合，還是進入子頁面？**
   - 選項 A（規格）：同頁展開/收合
   - 選項 B：彈出 dialog
   - **決定**：選項 A（規格要求「同頁展開」）
