## 1. 產品核心與範圍

### 已接受

- UVAlert 的首要目標是「防曬乳補擦倒數」。
- 使用者進入產品後，第一個要被回答的問題是：**「我這次擦的防曬，現在下一步該做什麼？」**
- 紫外線、溫度、地區與衛教資訊是重要輔助，但不能壓過倒數的主要操作。
- 不註冊也能使用核心功能，包括倒數、裝備紀錄、照片與分享圖片。
- 第一版以台灣、繁體中文、`Asia/Taipei` 時區與 TWD 為預設；價格幣別可編輯，資料結構需保留未來國際化空間。
- 第一版一台裝置只允許一個進行中的 Session，不做家庭成員、多使用者或多組同時倒數。

### 明確取消或延後

- 不要求註冊或登入後才能開始使用。
- 不把行為分析埋點納入產品。
- 不做分數、連續天數、完成率、排名、曬傷風險評分等遊戲化或推測性指標。
- 斗內支持功能延後到第二階段；第一版 Sitemap 不放。若日後加入，只能安靜地放在「更多／關於」，不可阻擋功能或出現在健康、安全、問題回報流程中。

## 2. 目前接受的 Sitemap 主架構

底部主導覽收斂為三個入口：

```text
提醒
├─ 尚未開始：開始提醒＋今日／明日 UV 輔助資訊
├─ 進行中：目前最需要處理的補擦狀態
└─ 頁內區塊－最近紀錄：預設顯示今天、昨天；30 天內的較早紀錄在同一頁收合

裝備
├─ 防曬乳（主要）
├─ 帽子
├─ 太陽眼鏡
├─ 陽傘
├─ 防曬衣物
└─ 其它防曬裝備

更多
├─ 防曬衛教
├─ 通知與 UV 地區
├─ 顯示與使用體驗
├─ 本機資料與隱私
├─ 問題回報與意見回饋
└─ 說明與關於
```

### 導覽原則

- 原本的「首頁」與「提醒」合併成同一個「提醒」入口，避免兩頁重複回答相同問題。
- 原本的「設定」改名為「更多」，因為內容已不只是設定，也包含衛教、回報與關於。
- 移除獨立的「過去提醒」入口，避免與「最近紀錄」重複。
- 首次開啟時可在免登入入口旁顯示次要的「使用 Google 登入並同步」入口；免登入／開始防曬提醒仍是主要操作，登入不得阻擋核心流程。完整帳號管理與重新登入仍可從「更多 → 本機資料與隱私」進入。
- 「最近紀錄」是提醒主頁內的內容區塊，不是獨立頁面或路由；放在主要倒數與操作之後。預設先顯示今天、昨天，30 天內的較早紀錄在原頁以次要區塊收合；查看或展開紀錄不會停止目前倒數。
- 裝備只有一個主入口：同一頁上方先顯示防曬乳，下方才是其它裝備。
- 防曬衛教的完整內容放在「更多」；提醒、UV、產品與皮膚不舒服等情境只放小型脈絡連結，不做阻擋式彈窗、輪播或資訊流。
- 「更多」頁採卡片／圖示入口；六個功能仍在同一頁直接進入，不增加下排導覽項目，也不把每個功能拆成新的主導覽入口。

### 晚間首頁

- 夜間 UV 很低時，不封鎖開始倒數。
- 尚未開始 Session 時，主要呈現「明日 UV 預測」；仍保留「開始防曬提醒」作為次要操作。
- 已有進行中的 Session 時，倒數仍是最高優先；明日 UV 預測退到輔助位置。
- 不提供預先排程明天 Session 的功能。

### 尚未開始 Session 的提醒頁

- 尚未開始時，提醒頁以一張「今日／目前 UV＋開始防曬提醒」主卡作為主要內容；卡片內提供簡短播報說明與主要「開始防曬提醒」按鈕。
- 開始 Session 後沿用同一主卡位置，切換為「補擦倒數為主、目前 UV／播報為輔」；不因開始前後改跳到另一個主頁。

## 3. 開始防曬提醒

### 設定方式

- 使用者從「提醒」按下「開始防曬提醒」後，進入一個獨立的完整設定頁。
- 產品、部位、時間、間隔與開始操作都在**同一個設定頁**完成，不再讓兩個步驟各自跳轉頁面。
- 取消或返回時回到「提醒」；成功開始後也回到「提醒」並顯示進行中狀態。
- 在 Sitemap 中，這是一個「提醒」底下的子頁，不拆成多個步驟頁。
- 頁面以漸進揭露分成兩組資訊：
  1. 防曬乳與這次有擦的部位。
  2. 擦拭時間、補擦間隔與開始提醒。
- 地區、戶外活動與防曬裝備不放進開始流程。
- 第一次開啟 App 直接進「提醒」，不先顯示註冊、教學輪播或權限要求。

### 防曬乳與間隔

- 若使用者確定擦了防曬，但不知道產品建議補擦間隔，使用 **120 分鐘**作為保守預設。
- 120 分鐘是通用的提醒上限／保守 fallback，不代表可安全曝曬 120 分鐘。
- 產品標示或實際事件要求更早處理時，以更早者為準。
- UV 指數不會自動延長或縮短防曬乳倒數。
- 無法確認使用的是防曬產品時，不建立 Session。
- 可用「這次先不儲存產品」開始；之後可從進行中畫面或結束摘要選擇儲存。
- 儲存成產品紀錄時，名稱必填。
- 若開始設定時找不到使用中的防曬乳，從目前設定頁開啟快速新增面板，不跳到完整裝備表單。
- 快速新增只要求產品名稱；品牌、SPF／PA、防水標示與產品標示的補擦間隔可選填。
- 照片、價格、心得等完整資料留到「裝備」補齊。
- 快速新增完成後，自動選取該瓶產品並回到原本的設定位置。
- 若 Session 開始時選擇「這次先不儲存產品」，之後要使用「換新的一瓶」時，必須先從進行中畫面儲存目前這瓶並填寫必填名稱；儲存不改變目前倒數，也不強迫跳出額外視窗。未儲存產品不能直接建立暫時新瓶。
- 「換新的一瓶」只能從目前產品紀錄的操作入口建立同款新瓶；同款關係由此入口建立，不以名稱或品牌文字自動比對。新瓶可沿用原產品識別，但仍是獨立瓶身紀錄。

### 上次設定與草稿

- 回訪使用者可沿用上次的產品、部位與間隔，但必須重新確認。
- 若上次預填的產品已過期、停用、刪除或其它無效，保留部位與間隔等可用預填，但產品欄改為依實際原因說明並要求更換有效產品；開始按鈕維持停用，不提供繞過。
- 不沿用上次 Session 的擦拭時間、倒數、事件或狀態。
- 未完成的設定草稿只保存產品、部位與間隔，不建立 Session，也不安排通知。
- 回到草稿時必須重新確認擦拭時間；跨日不可沿用舊時間。

### 擦拭時間

- 只能選「現在」或輸入過去的確切時間。
- 較早時間最多回填到過去 120 分鐘。
- 不提供未來時間。
- 不提供「不確定時間」。
- 若輸入後已到期，直接顯示需要處理。
- 若實際擦拭已超過 120 分鐘，提示使用者先完成一次真實補擦，再以「現在」開始，不捏造舊倒數。

### 第一次安全提示

- 第一次建立 Session 前顯示一次簡短安全說明。
- 後續不重複阻擋，但介面保留可再次查看的短連結。
- 不使用冗長、強迫式的免責同意書。

## 4. 防曬部位與多組倒數

### 固定部位

1. 臉部
2. 頸部與耳朵
3. 肩膀與手臂
4. 手部
5. 胸腹與背部
6. 腿部
7. 腳部

這些選項代表「這次確實有擦防曬、需要追蹤的部位」，不是要求使用者勾選所有裸露部位。

### 行為規則

- 提供常用組合與自訂選擇。
- Session 開始時，所有選取部位共用同一個初始擦拭時間。
- 第一次開始提醒且沒有既有偏好時，系統預先選取「臉部」；使用者仍可在開始前調整。
- 使用者完成一次開始設定後，記住該次開始時選定的部位，下一次開始流程預先帶入；這只是預填，不會自動建立新的 Session。
- Session 中途停止部位不會改寫上述預設；下次仍預填上一次開始 Session 時的部位選擇。
- 只補擦部分部位後，才拆分成不同倒數。
- 取消獨立的「修改防曬部位」入口、頁面與管理面板。
- Session 開始後，追蹤部位固定；進行中只能停止單一部位，不能新增或恢復部位。
- 若之後需要改成其它部位，須先結束目前 Session，再開始新的 Session；新 Session 預填原本的防曬產品與提醒間隔，使用者重新選擇部位並確認擦拭時間，不沿用舊 Session 的部位狀態與倒數。
- 要停止單一部位時，從目前部位的展開內容直接使用「不再提醒」；若要全部停止，使用「結束本次提醒」。
- 按下「不再提醒這個部位」後立即停止並從進行中畫面移除該部位；頁面下方提供固定 8 秒的「復原」。8 秒結束後，該部位不能在同一個 Session 內恢復。
- 若在 8 秒內連續停止多個部位，合併為一批待停止項目，提示顯示「已停止提醒 N 個部位｜復原全部」；每新增一個停止部位，便從該刻重新計時 8 秒，不堆疊多個提示，也不提供逐一復原。
- 復原停止部位時，視為停止從未發生，恢復該部位原本的到期時間；8 秒等待期間的實際時間仍照常經過。復原不得建立補擦紀錄、變更擦拭時間或重設完整提醒間隔。
- 停止部位事件採低干擾呈現：8 秒復原期結束後，才在可展開的「本次紀錄」與 Session 時間軸加入一行客觀紀錄；主倒數畫面與已結束紀錄的收合摘要不顯示。若在 8 秒內復原，完全不留下此事件。
- 若使用者在停止部位的 8 秒復原期內結束 Session，視為已確認停止：立即關閉復原提示、把停止事件寫入已結束 Session 的時間軸，不讓已結束的 Session 保留可操作的復原。
- 停止事件是特殊的部位狀態操作，不納入進行中「本次紀錄」的一般修改功能；超過 8 秒後只能查看，不能刪除、改時間或用修改功能恢復部位。一般修改仍可用於修正真正的補擦事件。
- 修改進行中的一般補擦事件時，部位只能從目前仍在提醒的部位中選擇；已停止或 Session 開始時未選的部位不列入選項，不能藉由修改恢復或新增追蹤。時間仍沿用現在或過去 120 分鐘內的確切時間限制。
- 進行中一般補擦事件的可修改時間還受 Session 邊界限制：不得早於 Session 開始時間；實際可選範圍為「Session 開始時間～現在」，且只有在 Session 開始時間早於現在 120 分鐘時，才以 120 分鐘回溯上限取較晚者。
- 停止某部位後，立即取消該部位尚未發送的補擦通知；已送出的系統通知無法收回。若在 8 秒內復原，恢復該部位後續的通知排程。
- 點擊停止前已送出的該部位通知時，仍開啟提醒頁，但不恢復部位、不建立倒數；頁面下方短暫顯示「手部已停止提醒」等狀態提示，讓使用者知道通知沒有重新啟用該部位。
- 點擊已結束 Session 的舊通知時，開啟提醒頁並短暫顯示「本次提醒已結束」；不建立新的 Session，也不重新啟動任何倒數。
- 若使用者已開始新的 Session，卻點擊上一個 Session 的舊通知，仍留在目前提醒頁並短暫顯示「這是已結束的提醒，目前提醒以最新 Session 為準」；不跳往舊歷史、不改變目前倒數，也不建立新 Session。
- 當 Session 只剩最後一個提醒部位時，不再顯示「不再提醒這個部位」，改為「結束本次提醒」，並沿用既有的同頁結束確認；不得產生沒有任何提醒部位、卻仍在進行中的空 Session。
- 停止追蹤不刪除既有歷史。

### 已確認的白話文案方向

- 「調整追蹤部位／修改防曬部位」獨立入口取消，不再建立專用頁面或面板。
- Session 進行中不提供新增或恢復部位；若部位需求改變，結束目前 Session 後再以預填的產品與間隔開始新 Session。
- 停止操作：**不再提醒這個部位**
- 停止後提示：**已停止提醒「手部」｜復原**；部位名稱依實際操作替換，提示保留 8 秒。
- 連續停止多個部位時，提示合併為：**已停止提醒 N 個部位｜復原全部**。
- 只剩最後一個部位時，操作改為：**結束本次提醒**，不再使用停止單一部位的文案。
- 停止事件只在展開紀錄時顯示：**14:30　停止提醒・手部**；不增加主畫面的常駐文字。
- 停止事件不可透過「修改」恢復；要撤銷只能在 8 秒內按「復原」。
- 一般補擦事件的修改文案只呈現目前可選的追蹤部位，不顯示已停止或未追蹤部位。
- 已送出的停止前通知若被點開，只開啟提醒頁，不重新加入該部位或建立倒數；該部位仍依目前停止狀態處理。
- 「更正最近事件」取消，改用：**最近紀錄**。只有進行中 Session 的「本次紀錄」提供 **修改**；已結束 Session 為唯讀。
- 尚未追蹤或已停止的部位不出現在進行中的主畫面與補擦流程，也不能在同一個 Session 內恢復。

完整文案仍待所有問題問完後統一整理，避免局部文案彼此不一致。

## 5. 進行中的提醒畫面

- 進入提醒頁後，補擦倒數與目前 UV／播報資訊合併在同一張主資訊卡；倒數數字是最大、最醒目的內容，UV 狀態與一句播報說明作為輔助，不另做成搶走核心的獨立首頁。

### 資訊層級

- 主畫面只有一張主要操作卡，聚焦在「現在到期／下一組到期的部位」。
- 其它不同時間的倒數合併成 **其它部位**，不顯示「其餘 5 個」這類帶數字且有壓迫感的標籤。
- 「其它部位」可展開查看實際部位名稱。
- 若所有部位時間相同，顯示 **所有防曬部位**，不再另外顯示「其它部位」。
- 不使用語意模糊的「尚有時間」。
- 已停止追蹤的部位不出現在進行中主畫面。

### 補擦

- 補擦流程用同頁底部面板／展開區完成，不跳到多個頁面。
- 補擦流程只顯示目前正在提醒的部位；尚未追蹤或已停止的部位完全不顯示。
- 已到期部位預先選取，但使用者可調整。
- 未到期部位仍可選取。
- 沒有任何部位到期時，不預先選取任何部位。
- 補擦時間可選現在或過去 120 分鐘內的確切時間。
- 只有使用者選取且確實補擦的部位會重設倒數。

### 結束 Session

- 「結束本次提醒」是次要操作，使用同頁確認，不要求填寫結束原因。
- 結束後顯示摘要。
- 結束的 Session 不重新開啟；若是誤操作，可用原設定預填一個新 Session。
- Session 不會因時間經過而自動結束。

### 長時間沒有有效紀錄

- 連續 12 小時沒有「有意義的紀錄」時，進入恢復判斷畫面，而不是自動結束。
- 有意義的紀錄是已儲存的補擦或事件；只開啟 App 不算。
- 恢復畫面不可直接按「繼續倒數」。使用者必須選擇：
  - 記錄過去 120 分鐘內實際發生的補擦與部位；
  - 現在補擦；
  - 結束舊 Session；
  - 結束舊 Session 並用預填設定開始新的 Session。
- 跨日且狀態過舊時，也使用相同恢復機制。
- 進行中的 Session 不套用「結束後保留 30 天」的自動刪除規則；即使長時間未處理，仍維持上述恢復判斷，由使用者明確結束或建立新 Session。

## 6. 會影響提醒的事件

### 第一層事件

- 洗手
- 大量流汗
- 游泳或長時間／大量碰水
- 擦拭或明顯摩擦
- 使用後皮膚不舒服
- 「已補擦」是獨立的主要操作，不混在一般事件清單中。

### 雨天

- 不新增一個常駐的「淋雨」第一層選項，避免事件過多。
- 明顯淋濕時，從「游泳或長時間／大量碰水」內選擇淋雨情境。
- 只有少量雨滴時不要求紀錄。
- 同一流程詢問是否有用毛巾擦乾；這可能影響需要立即處理的判斷。

### 事件時間

- 預設為現在，也可輸入較早的確切時間。
- 明確不提供「不確定時間」。若完全無法估計，取消事件紀錄，改在完成真實補擦後記錄。
- 可輸入範圍為 Session 開始至現在，不允許未來或早於初次擦拭。
- 碰水事件的結束時間不可早於開始時間。

### 預選部位

- 洗手：只預選「手部」；未追蹤手部時隱藏此事件。
- 大量流汗、游泳或大量碰水：預選所有目前追蹤部位，可編輯。
- 擦拭／摩擦、皮膚不舒服：不預選，由使用者選擇。
- 任何事件至少要選一個受影響部位才可儲存。

### 倒數影響

- 洗手、擦拭或明顯摩擦：受影響部位標示為現在需要處理；其它部位保持原倒數。
- 防水標示只有明確寫 40 或 80 分鐘時才套用碰水期限。
- 碰水／大量流汗後，以「原本到期時間」和「事件開始後 40／80 分鐘」兩者較早者為準。
- 產品沒有明確防水標示或標示不明時，不替產品捏造 40／80 分鐘。
- 不加入室內／室外切換，也不讓帽子、陽傘或衣物自動改變防曬乳倒數。

### 皮膚不舒服

- 使用者明確確認後，結束目前 Session，並把該瓶產品標示為停用。
- 保留產品基本紀錄與照片，但該瓶不可再用來開始 Session。
- 不要求症狀自由文字、身體照片或醫療史，也不做診斷。
- 若是誤標，從該瓶防曬乳詳情使用專用的誤標恢復操作；確認後重新啟用產品，並將原「皮膚不舒服」事件標示為已撤回。舊 Session 不重新開啟，也不影響目前倒數。

## 7. 歷史紀錄

- 直接從提醒主頁內的「最近紀錄」區塊查看紀錄；預設顯示今天、昨天，30 天內的較早紀錄在同一頁收合，不另設「最近紀錄」或「過去提醒」獨立頁。
- 若有進行中 Session，「本次紀錄」固定放在最上方；已結束的 Session 再依「今天」、「昨天」與收合的「較早紀錄」排列，不把目前事件混入歷史時間軸，也不另拆分頁。
- 沒有進行中 Session 時，整個「本次紀錄」區塊隱藏，不保留空卡，也不在該區重複放置「開始提醒」按鈕；已結束紀錄直接往上排列。
- 完全沒有進行中或已結束紀錄時，保留「最近紀錄」區域並顯示精簡空狀態，說明完成一次防曬提醒後會在這裡出現紀錄；不放大型插圖，也不重複放置開始按鈕。
- 「今天／昨天／較早紀錄」依 Session 的開始日期分組；跨日 Session 不拆開，也不因隔天才結束而移到結束日。此規則只影響畫面分組，30 天保存期限仍從結束時間起算。
- 同一日期群組內，已結束 Session 依開始時間由新到舊排列，不提供自訂排序切換。
- 已結束 Session 尚未展開時，只顯示開始～結束時間、防曬乳名稱，以及「中斷」或仍有效的「皮膚不舒服」等必要特殊狀態；已撤回事件不再顯示於收合摘要。不顯示部位摘要、補擦次數、事件數或一般結束原因。
- 同一時間只展開一筆已結束 Session；展開另一筆時自動收合上一筆。事件時間軸與操作留在同一頁，不跳往獨立詳情頁。
- 展開較早紀錄後，可查看 Session 清單與單次時間軸。
- 已結束的提醒紀錄在本機保留 30 天；超過保留期後自動永久刪除，不採無限期累積。
- 30 天從 Session 的結束時間起算；到期時刪除整個 Session 與其事件時間軸，不逐筆拆開刪除。
- 到期前不傳送系統通知，也不另外顯示主動式 App 內警告；只在「最近紀錄」與本機資料管理中固定說明「已結束的提醒紀錄保留 30 天」。
- 歷史只呈現事實：日期、時間、產品、部位、事件、狀態與客觀次數。
- 不顯示分數、完成率、排名、曝曬程度或曬傷風險推測。
- 已結束 Session 的事件時間軸為唯讀，不提供逐筆修改時間、部位、事件或刪除單一事件；需要移除錯誤歷史時，使用者可刪除整個 Session。
- 進行中 Session 的「本次紀錄」仍可修改，因為更正時間或部位可能影響目前倒數；此能力不延伸到已結束 Session。
- 從產品詳情撤回誤標的「皮膚不舒服」是產品停用狀態的專用恢復流程，不視為開放歷史的一般編輯能力。
- 已撤回的「皮膚不舒服」事件仍以較弱樣式保留在展開的唯讀時間軸，直到整個 Session 被使用者刪除或結束滿 30 天自動刪除；不套用刪除 Session 時的 8 秒復原期限。
- 可刪除單一過去 Session：在展開的紀錄中提供明確可見的「刪除這次紀錄」，不把滑動手勢當成唯一入口。
- 按下後不跳頁、不再顯示確認框；先從畫面移除，並在頁面下方提供 8 秒的「復原」。8 秒以固定實際時間計算，不因頁面進入背景、滑鼠停留或鍵盤焦點而暫停；時間結束後才視為永久刪除。
- 若在 8 秒內連續刪除多個 Session，合併為同一批待刪除項目，提示顯示「已刪除 N 次紀錄」並只提供「復原全部」；每新增一筆刪除便從該刻重新計時 8 秒，不堆疊多個提示。
- 「清除所有提醒紀錄」放在本機資料管理；裝備資料分開處理。
- 「清除所有提醒紀錄」必須先顯示確認框，列出即將刪除的 Session 數量，並明確說明裝備資料不受影響；確認後永久刪除，不提供 8 秒復原，也不要求輸入確認文字。
- 「清除所有提醒紀錄」只清除已結束的 Session；若目前有進行中 Session，仍可清除歷史，確認框數量不包含目前 Session，且目前倒數、事件與通知完全不受影響。
- 清除完成後留在本機資料管理頁，不自動跳轉；確認框關閉，顯示「已清除 N 次提醒紀錄」，並把已結束紀錄數量更新為 0。
- 有進行中 Session 時，只有清除整份網站資料或備份還原等會影響目前狀態的操作必須先結束 Session；單純清除已結束的提醒紀錄不受此限制。

## 8. 防曬乳產品規則

### 一瓶一筆

- 一筆產品紀錄代表一個實際瓶身，不把相同品名的不同瓶合併。
- 相同產品用完後，建立下一瓶的操作名稱固定為：**換新的一瓶**。
- 「再次購買」與「新增同款」均不採用。
- 按下「換新的一瓶」後，先在原本的流程中開啟已帶入上一瓶資料的新瓶表單；舊瓶所有欄位保持不可修改。
- 新瓶在儲存前是獨立的新紀錄，可調整瓶身資料（主要照片、尺寸、價格／幣別、購買或取得日期、有效期限、使用感受、備註）；產品識別資料（名稱、品牌、SPF／PA、型態、防水標示、標示補擦間隔）維持同款並鎖定。
- 儲存新瓶後，舊瓶移到過往，新瓶列為目前使用；表單本身就是必要確認步驟，完成後不再額外跳出成功提示或確認視窗。
- 新瓶表單尚未儲存時離開：若完全沒有修改，直接返回；若已修改，先顯示「尚未儲存，要離開嗎？」讓使用者選擇捨棄離開或繼續編輯。不保存新瓶草稿；在儲存前舊瓶、目前倒數與 Session 都不受影響，也不建立時間軸事件。
- 舊瓶仍可查看與分享，但不可開始新的 Session。

### 欄位

- 必填：名稱。
- 選填：品牌、主要照片、SPF／PA、型態、尺寸、價格／幣別、購買或取得日期、有效期限、防水標示、標示補擦間隔、使用感受、備註。
- 支援型態：乳液、乳霜、凝膠、防曬棒、噴霧。
- 第一版倒數不納入 SPF 彩妝／蜜粉、護唇產品、無法辨識的產品或口服產品。
- 使用感受不採 1～5 星。採三段選擇，例如「很喜歡／還可以／不適合我」，並可補充文字；最終詞句待統一文案階段確認。

### 產品與 Session 的關係

- 一個 Session 以同一款防曬乳為主；一般情況不在 Session 中切換不同產品。若是同款產品換新的一瓶，可在不中斷 Session 的情況下更新瓶身紀錄。
- 明確取消「不同身體部位使用不同產品」的多產品設計。
- 同一瓶不可在 Session 途中被編輯成另一個產品。
- 同一款產品換新瓶時，可在不中斷 Session 的情況下切換瓶身紀錄；這個動作不算補擦，且不改變任何部位倒數。
- 同一個 Session 可重複換新同款產品；每次換新都把上一瓶移到過往，並把下一瓶列為目前使用，不限制換瓶次數。
- 換新後只提供「切回上一瓶」作為誤選修正；不提供任意選回更早的過往瓶，也不因此改變倒數或新增時間軸事件。
- 「切回上一瓶」是最近一次換新的單次撤銷：上一瓶恢復為目前使用，剛換出的瓶子回到過往；完成切回後不能再切回剛才那瓶，也不能改選更早瓶身。
- 「切回上一瓶」在 Session 尚未結束前都可使用；Session 結束後產品狀態與歷史時間軸唯讀，不再提供切回。
- 每次再次換新都只更新一次切回權限：第三瓶只能切回第二瓶；切回第二瓶後，這次撤銷完成，不能再切回第三瓶或更早的第一瓶。
- 如果換新後沒有切回就結束 Session，直接以當下目前瓶身狀態結束；未使用的切回權限隨 Session 失效，不在結束摘要或歷史中額外標示。
- 換新的一瓶完成後不跳出額外成功提示或確認視窗；儲存後產品區直接更新為目前的新瓶資料，讓狀態透過原本的畫面呈現反映變更。
- 同款換新瓶不在「本次紀錄」或已結束 Session 的時間軸留下獨立事件；它只影響產品／瓶身資料的關聯，不增加提醒操作紀錄。
- 已結束 Session 的產品欄位只顯示同款產品名稱，不顯示特定瓶身、購買日期或瓶身細節；名稱採 Session 的不可變產品名稱快照。各瓶的完整資料仍在「裝備」查看。
- 若改用不同產品，結束舊 Session，再用既有資料預填新 Session。
- 編輯產品目錄不會改寫進行中或過去 Session；Session 保存當時的不可變產品快照。
- 若進行中 Session 所使用的產品之後被標記為停用、過期或其它無效，Session 仍依建立時的產品快照與原倒數繼續；這些產品狀態只阻止未來開始新的 Session，不默默改寫目前倒數。已確認的「皮膚不舒服」事件仍是例外，會直接結束目前 Session 並停用產品。
- 進行中 Session 不因產品後續停用、過期或無效狀態在提醒頁增加額外提示；提醒頁維持倒數與主要操作，產品實際狀態留在「裝備」與下一次開始流程中呈現。

### 無效、停用與刪除

- 明確過期、保存年限無法確認且無有效期限、或外觀／氣味／質地異常的產品，不可開始 Session。
- 不提供「仍要繼續使用」的繞過按鈕。
- 製造商與所在地標示優先；美國 FDA 的三年規則只能作為具司法轄區說明的 fallback，不可直接套用到所有產品。
- 「停止使用」可恢復；「永久刪除」不可恢復。
- 刪除產品後，過去 Session 只保留最低限度的產品名稱快照；私人欄位與照片刪除。
- 進行中 Session 使用的產品，必須先結束 Session 或更換後才能永久刪除。

### 這次未儲存的產品

- Session 開始後不強迫跳出儲存視窗。
- 進行中畫面與結束摘要提供次要「儲存這瓶防曬」入口。
- 儲存時名稱必填；建立產品紀錄不回頭改寫 Session 的產品快照。

## 9. 其它防曬裝備

### 定位

- 帽子、太陽眼鏡、陽傘、防曬衣物與其它裝備只提供個人紀錄，例如好不好用、價格與何時取得。
- 這些裝備不進入 Session，也不改變防曬乳倒數。
- 裝備頁與分享功能仍以防曬乳為優先，再逐步支援其它裝備。
- 若尚未建立任何防曬乳，裝備頁留在原頁顯示精簡空狀態，提供主要「新增防曬乳」與次要「先看看其它裝備」入口；不自動跳到開始提醒、不要求登入，也不影響提醒頁內的快速新增。

### 欄位

- 必填：名稱。
- 選填：品牌、主要照片、價格／幣別、取得日期、標示資訊（例如照錄 UPF／UV400）、尺寸、三段使用感受、備註。
- 尺寸為自由文字，且可選擇是否放進分享圖片。
- 其它裝備可在詳情頁直接編輯所有欄位；修改只影響之後產生的分享圖片，不回溯或改變已下載、已分享的圖片。
- 刪除其它裝備前先確認；確認後立即從列表移除並刪除其本機照片，提供 8 秒「復原」。超過 8 秒後永久刪除，不進入封存區，也不影響任何 Session、倒數或提醒。

## 10. 裝備分享圖片

- 產品與裝備可產生靜態分享圖片，讓使用者把個人使用心得分享給朋友。
- 不建立公開產品頁、社群、留言、排行榜或帳號系統。
- 未註冊使用者也能使用。
- 每筆裝備先支援一張主要照片，可從相簿或相機加入並在本機裁切。
- 分享卡預設可含：照片、品牌／名稱、三段使用感受、使用者確認過的短分享文字。
- SPF／PA、防水標示、價格與尺寸為選填。
- 不放購買／取得日期、有效期限、Session、身體部位、位置、皮膚不舒服紀錄或私人完整備註。
- 產生前先預覽並允許編輯；預覽中的短分享文字、顯示欄位與圖片裁切只套用到這一次分享，不改寫裝備原始紀錄。若要永久修改，必須回到裝備詳情頁另行編輯。優先使用 Web Share，無法使用時提供下載圖片。
- 若分享圖片產生失敗，或使用者取消系統分享／下載，保留目前預覽編輯內容並停留在分享預覽頁，顯示原因與「再試一次」；不改寫裝備原始紀錄，也不建立分享草稿。
- 分享成功或圖片下載完成後仍留在分享預覽頁，顯示簡短成功狀態，提供「回到裝備詳情」與再次分享；不自動跳回列表或其它頁面。
- 「分享圖片」的主要入口只放在「裝備」詳情頁；裝備列表不提供第二個直接分享入口，先進入詳情確認資料後再進入分享預覽。
- 產生的分享圖不永久保存；需要時由目前資料即時產生。
- 匯入照片在本機最佳化與重新編碼，移除 EXIF 中的 GPS、裝置與拍攝時間；不改動使用者相簿原檔。
- 照片處理或儲存失敗時，文字紀錄仍可保存。
- 技術實作方向為：IndexedDB 中將圖片與文字資料分開儲存；正式實作前仍需以瀏覽器支援矩陣驗證。

## 11. 本機資料、備份與隱私

### 匿名使用

- 倒數、裝備、照片與分享都能完全在不註冊情況下使用。
- 若未來加入帳號，只能作為選用的同步／還原功能，不得變成核心功能門檻。
- 後續版本可提供選用的 Google 帳號登入；登入後由使用者明確選擇是否把資料同步到 UVAlert 雲端。免登入核心流程、本機資料與加密備份仍可使用，Google 登入不提高倒數或 UV 準確度，也不等同於 Google Drive 備份。

### 匯出與還原

- 本機備份包含文字資料與主要裝備照片，不包含即時產生的分享圖。
- 完整備份不包含裝置專屬的補擦通知偏好、瀏覽器／系統通知權限或 Web Push 訂閱；還原不得覆蓋目前裝置的通知設定，新裝置沿用自身設定或初始預設「只提醒一次」。
- 完整備份必須由使用者密碼加密，不提供明文完整備份。
- 密碼不儲存、不上傳，也無法代為找回。
- 建立備份時由使用者自行輸入至少 8 個字元的密碼並再次確認；採簡單長度規則，不強制大小寫或特殊符號，允許貼上與使用密碼管理器。畫面明確說明密碼不會儲存，忘記後無法還原。還原時必須輸入同一組密碼。
- 還原採「整份取代」，不做合併。
- 還原前先在暫存區驗證、顯示摘要、建立安全副本；失敗時回滾，不留下半套資料。
- 還原時密碼錯誤，留在還原流程顯示「密碼不正確，無法讀取備份」並提供重新輸入；在成功驗證前目前資料完全不變。
- 若備份含有已超過 30 天保留期的提醒紀錄，還原時直接略過；裝備等其它仍有效的資料照常還原。
- 還原摘要必須顯示略過了多少筆過期提醒紀錄，不可讓資料無聲消失，也不可藉由還原讓過期紀錄重新出現。
- 進行中 Session 時不可還原，必須先結束。
- 備份中仍在 30 天保留期內的未完成 Session，還原後只列為「中斷的歷史紀錄」，不自動續跑；可沿用設定建立新 Session。

### 錯誤回報與遙測

- 不做行為分析。
- 匿名錯誤回報預設關閉，使用者可選擇開啟。
- 可傳送的最低限度診斷資料：錯誤堆疊、App 版本、瀏覽器／作業系統與時間。
- 不傳使用者文字、產品、照片、部位、位置、皮膚不舒服紀錄或備份內容。

## 12. 通知、PWA 與離線

### 技術誠實性

- PWA 在 App 關閉後，不能只靠前端本機計時保證準時通知。
- 核心背景提醒採匿名 Web Push，需有網路；App 開啟時可使用前景本機提醒。
- 離線或平台限制下，不承諾 App 關閉後一定準時送達，介面必須直接說明限制。
- 瀏覽器／系統通知權限已允許，不代表 Web Push 註冊一定成功；介面必須分開呈現這兩種狀態。
- 若 Web Push 因斷線或伺服器錯誤而註冊失敗，Session 與前景倒數照常運作，不阻止或回滾 Session。
- 提醒頁顯示簡短的「背景通知尚未設定完成」狀態；「更多 → 通知設定」提供完整說明與「重新嘗試」。
- 註冊失敗時不可顯示為通知已成功開啟，也不可再次呼叫系統權限視窗。
- Web Push 註冊失敗後，若 App 正在開啟並偵測到恢復連線，自動重試一次。
- 自動重試成功後安靜更新為可用；再次失敗便停止自動重試，只保留手動「重新嘗試」。
- 重新註冊成功後只安排未來通知，不補送斷線期間已錯過的提醒。

### 權限與安裝

- 不在第一次開啟 App 時要求通知權限。
- 第一個 Session 建立成功後，先進入「提醒」並顯示已開始的倒數，不讓通知權限流程擋在倒數前面。
- 接著在提醒頁顯示不阻擋操作的通知說明卡；卡片直接顯示目前預設為「只提醒一次」，只有使用者按下「開啟通知」後，才呼叫瀏覽器／系統權限視窗。
- 通知說明卡提供選填的「調整提醒方式」入口，直接在同一提醒頁展開設定；不要求所有人先完成設定，也不跳轉至獨立設定頁。權限成功、取消或失敗後皆留在目前倒數頁。
- 若使用者選擇稍後，Session 與前景倒數仍正常運作，但需清楚說明 App 關閉後可能收不到背景通知。
- 第一次選擇「稍後」後，本次 Session 不再顯示；下一次建立新 Session 時可再主動詢問一次。
- 若第二次仍選擇「稍後」，之後不再自動顯示通知說明卡，只保留「更多 → 通知設定」入口。
- 使用者主動開啟高 UV 提醒時，也可提供相同的權限說明與請求。
- 若使用者已在瀏覽器／系統權限視窗選擇「拒絕」，立即停止所有自動提示，不套用上述第二次詢問；「更多」只提供平台設定協助。
- 若使用者日後從手機或瀏覽器設定關閉 UVAlert 通知，App 下次開啟時顯示「系統通知已關閉」，不可繼續顯示成通知可用。
- 保留使用者原本選擇的補擦通知與高 UV 通知偏好，但暫停實際推播，並刪除已無法使用的伺服器推播訂閱。
- 「更多 → 通知設定」提供符合目前裝置的重新開啟說明；Session 與前景倒數不受影響。
- 使用者從手機或瀏覽器設定重新允許通知後，App 下次在前景開啟時，依原本保留的偏好自動重新建立 Web Push，不要求再完成一次通知設定。
- 恢復成功後只安排未來通知，並顯示簡短的「背景通知已恢復」狀態；若失敗，沿用既有的自動一次與手動重試流程。
- PWA 可直接在瀏覽器使用。
- 安裝提示只在第一次 Session 後或開啟通知時脈絡式出現；不做首次開啟的全頁安裝廣告。
- 關閉提示後記住選擇，「更多」保留永久安裝說明。
- iOS 只在需要時顯示符合該平台的加入主畫面說明。

### 補擦通知

- 到期時立即通知一次；若使用者選擇再次提醒，未處理時可在 15 或 30 分鐘後最多再提醒一次。
- 到期時若 UVAlert 頁面正在前景顯示，倒數卡改成需要補擦狀態並顯示不阻擋操作的頁內提醒，不重複發送系統通知；頁面在背景、分頁已切走或 App 已關閉時才發送系統通知。
- 頁內提醒與系統通知都算該波的第一則提醒，兩者共用「最多再提醒一次」限制，不得因通道不同而多算一則。
- 2026-08-10 已確認要讓使用者自行選擇是否再次提醒，並將「再次提醒的選擇」和「什麼時候停止再次提醒」拆成兩個獨立設定；首次預設為只提醒一次。
- 同一個未處理到期狀態最多兩次，不持續轟炸。
- 同時間到期的部位合併成一則通知。
- 不同時間到期的部位也不各自堆疊通知；同一時間只維持一則代表「目前需要補擦部位」的通知。
- 前一組仍未補擦而有新部位到期時，更新／取代原通知，內容合併所有目前到期部位。
- 使用者完成部分補擦後，更新目前顯示的系統通知：已處理部位移除，仍到期的部位保留。
- 所有到期部位處理完成或 Session 結束時，立即嘗試撤掉該波仍顯示的系統通知並取消尚未發出的第二次提醒；不另發「已完成」通知。
- 若平台未能撤掉舊通知，之後點擊時仍只開啟 App 的目前提醒頁並讀取最新狀態；不得重新顯示已處理部位或復活已結束的到期波次。
- 同一波未處理狀態中有新部位到期時，只靜默更新合併通知，不再次響鈴或震動。
- 若使用者選擇再次提醒，第二次提醒從最早仍未處理部位的到期時間加上所選間隔計算；新部位加入不重設或延後這個時間。若選擇只提醒一次，便不套用此規則。
- 所有到期部位都處理完成後，下一個新到期部位才開始一波新的通知。
- 通知顯示需要的動作與部位，不放產品、私人或健康資訊。
- 點通知只開啟 App 並聚焦到期部位；不能從通知直接標記已補擦。
- 本機以版本／修訂狀態抑制過期通知；無法確定狀態時只顯示一般提醒。

### 補擦通知偏好架構

- 永久設定入口放在「更多 → 通知設定 → 補擦通知」，不放進「開始防曬提醒」流程。
- 第一次主動開啟通知時沿用「只提醒一次」預設；使用者可選擇在同一張說明卡展開調整，但不強迫多做一步。之後從「更多」修改。
- 第一次通知說明卡的「調整提醒方式」先顯示補提醒間隔與條件式停止規則，底部再提供第二層 **聲音與震動（選用）**；只有使用者主動展開後才顯示兩個開關與裝置測試流程。不得把聲音／震動設為開啟通知前的必填步驟，也不為此跳轉頁面。
- 第一個設定回答「是否需要再次提醒，以及隔多久」，第二個設定回答「記錄已補擦或點開通知後，何時停止再次提醒」。
- 「追加提醒頻率」被判定為不容易理解，不可直接作為最終介面文案。
- 暫定用更白話的問題 **「還沒處理時，要再提醒一次嗎？」** 表達第一個設定；選項與完整文案待所有問題問完後統一改寫。
- 第一版的再次提醒選項固定為：**只提醒一次**、**15 分鐘後再提醒一次**、**30 分鐘後再提醒一次**。
- 不提供 60 分鐘後再次提醒，也不讓使用者輸入任意分鐘數；每一波最多再次提醒一次，不做無限循環通知。
- 15／30 分鐘是到期後的通知間隔，不是延長防曬有效時間，也不是醫療上的安全寬限期。
- 首次預設選擇為 **只提醒一次**；使用者可在第一次主動開啟通知時改選 15 或 30 分鐘後再提醒一次，之後也可從「更多 → 通知設定 → 補擦通知」修改。
- 若使用者選擇 15 或 30 分鐘後再次提醒，第二個設定可選 **完成處理後才停止補提醒** 或 **點開通知後就停止補提醒**。
- 選擇「只提醒一次」時不顯示第二個停止條件；只有改選 15 或 30 分鐘後再次提醒時，才在同一區域展開這項設定。不可顯示成無作用的停用欄位，也不可讓它在只提醒一次時仍可修改。
- 改成「只提醒一次」只隱藏停止條件，不清除目前裝置上次選擇；之後再改回 15 或 30 分鐘時恢復原選擇。只有從未設定過的人才使用「完成處理後才停止補提醒」預設。
- 第二個設定預設為 **完成處理後才停止補提醒**：只有按下「已補擦」、「不再提醒這個部位」或結束本次防曬提醒，才停止該波後續通知；單純點開通知不算完成處理。
- 使用者若主動改成「點開通知後就停止補提醒」，點通知只代表已看過並取消該波後續通知，不得因此建立補擦紀錄或重設部位倒數。
- 使用者選擇「點開通知後就停止補提醒」時，點擊事件一發生便先在本機記錄為已看過；不必等待提醒頁完整載入或連上伺服器。當下離線也停止該波補提醒，恢復連線後再同步確認狀態。
- 「點開通知後就停止補提醒」在前景採 A＋B 混合判定：若使用者正在「提醒」頁且到期卡片實際位於可視範圍，卡片出現便自動算已看過；若人在 UVAlert 其他頁面或到期卡不在可視範圍，必須點擊頁內提醒後才算已看過，並聚焦到期部位。
- 頁面在背景、分頁已切走或 App 已關閉時，仍以點擊系統通知作為已看過。上述三種「已看過」都只取消該波第二次提醒，不得建立補擦紀錄、重設倒數或影響選擇「完成處理後才停止」的使用者。
- 若目前瀏覽器／裝置無法可靠確認通知點擊，保留「點開通知後就停止補提醒」選項的位置但設為不可選，並簡短說明此瀏覽器無法確認通知是否已點開；不得直接隱藏，也不得把同一選項偷偷改成「成功進入提醒頁才算」。
- 設定頁需說明補擦通知偏好只套用在目前裝置／瀏覽器；不註冊使用不影響設定與通知本身的可用性。
- 「更多 → 通知設定 → 補擦通知」另提供獨立的 **頁內提醒聲音** 開關，只控制 UVAlert 正在前景時的到期提示音；不控制背景系統通知的聲音、震動或手機音量，這些仍由瀏覽器／作業系統決定。
- 頁內提醒聲音首次預設關閉，由使用者主動開啟；它屬目前裝置／瀏覽器的偏好，不跨裝置同步，也不放入完整備份。
- 使用者開啟頁內提醒聲音後，同一波的第一則頁內提醒與排定的第二則頁內提醒各播放一次短聲音；不得循環播放。中途新增到期部位或合併更新既有提醒時只更新畫面，不額外發聲。
- 第一版只使用一種短而柔和的固定提示音，設定旁提供「試聽」；音量跟隨裝置媒體音量，不增加 App 內音量滑桿，也不提供多音效選擇或自訂上傳。
- 目前專案內沒有既有音檔；已確認以 Kenney `Interface Sounds`（CC0）作為主要素材來源，實際採用哪一個檔案留待後續試聽決定，目前尚未下載或加入任何音檔。正式加入時需一併保存來源網址與授權紀錄。
- 使用者開啟頁內提醒聲音時，需立即以同一提示音進行目前裝置試聽；只有瀏覽器回報可開始播放後，開關才維持開啟。不得把「播放請求成功」描述成使用者一定聽得到，因為裝置仍可能靜音或音量為零。
- 若試聽被瀏覽器阻擋、發生錯誤或不支援，開關回到關閉，說明目前無法播放並提供重新試聽；視覺提醒與倒數不得受影響。
- 「更多 → 通知設定 → 補擦通知」另保留獨立的 **頁內提醒震動** 開關，不與聲音綁在一起；首次預設關閉，只保存在目前裝置／瀏覽器，不跨裝置同步，也不放入完整備份。
- 只有目前裝置與瀏覽器支援、並完成目前裝置震動測試後，震動開關才可保持開啟；不支援時顯示不可用原因，測試失敗則維持關閉。無論結果如何，視覺提醒與倒數都必須正常運作。
- 使用者開啟頁內提醒震動時，在同一設定頁先發出一次短震動，接著詢問「有感覺到震動嗎？」；選擇「有」才保持開啟，選擇「沒有」則回到關閉並提供重新測試。不得只依 API 回傳值判定使用者實際感受到震動，也不得為測試跳轉頁面。
- 頁內震動開啟後，同一波第一則頁內提醒與排定的第二則頁內提醒各短震一次，不使用連續或複雜節奏；中途新增到期部位與合併更新既有提醒時不額外震動。
- 若頁內提醒聲音與震動都已開啟，兩者在同一次頁內提醒一起發生；仍受同一波最多兩次限制，不另外增加提醒次數。
- 進行中的 Session 修改「只提醒一次／15 分鐘／30 分鐘」後，立即調整尚未發出的第二次提醒：改成只提醒一次就取消；15／30 分鐘互換時，若重新計算的時間仍在未來便改排新時間。
- 若重新計算出的提醒時間已經過去，不得立刻補送造成突襲；本波不再補發，從所有目前到期部位處理完成後的下一波到期開始套用新間隔。
- 這些設定只影響系統通知，不修改產品標示／120 分鐘 fallback 所決定的部位倒數，也不影響獨立的高 UV 日提醒。

### 離線

- 離線時仍可查看與操作本機 Session、產品、裝備與歷史。
- 明確顯示背景通知目前無法重新排程。
- 恢復連線後只安排未來通知，不補送離線期間累積的通知。

### 系統時間異常

- 倒數以經過時間與絕對時間共同核對；時區改變不重設 Session。
- 偵測到不合理的系統時鐘變動時，要求使用者重新確認，不允許因此延長倒數。
- 無法安全判定時，相關部位視為需要處理，並留下系統紀錄。

## 13. UV、地區與高 UV 提醒

### 地區

- 手動選擇台灣縣市是主要方式。
- 可選擇一次性使用目前位置；只保存解析後的縣市，不保存經緯度或位置歷史。
- 可選擇「每次開啟 App 時更新地區」，只在前景執行。
- 不提供真正的背景定位，因為 PWA 無法在各平台可靠支援，也不是核心倒數所需。
- Session 不要求位置，開始流程也不放位置設定。

### UV 呈現

- UV 只提供情境參考，不自動修改防曬乳倒數。
- UV 服務不可用時，Session 與倒數仍正常。
- 只使用日期相符且仍有效的快取；不可把昨天資料當今天，也不可猜測數值。
- 目前中央氣象署預報資料可支援「白天最高 UV 指數」，不能聲稱有精確的「今天 UV 最強時間點」。
- 因此介面顯示今天白天最高 UV 預測，不顯示不存在的精確峰值時間。

### 高 UV 日提醒

- 與補擦通知分成兩個獨立開關。
- 預設關閉。
- 開啟時，預設門檻為 UVI ≥ 6；使用者可提高為 8 或 11。
- 預設 08:00，使用者可修改時間。
- 使用已儲存縣市，不使用背景定位。
- 一天最多一次。
- 若當天已錯過設定時間，不補送，從隔天開始。
- 只有取得有效預報時才發送，不猜測。
- 伺服器只保存匿名推播訂閱、縣市代碼、門檻、通知時間／時區與開關，不保存 GPS、帳號、Session 或產品。
- 關閉高 UV 提醒時刪除相應資料；兩種通知都關閉時刪除推播訂閱。

每日「出門前擦防曬」提醒屬未來功能，不納入目前版本。

## 14. 防曬衛教

### 一級分類

1. 了解今天的 UV
2. 出門前準備
3. 外出中的補擦
4. 流汗或碰水後
5. 回家後與皮膚照顧
6. 特殊情況

- 衛教首頁目前採六個主題分類與少量推薦文章並列；分類名稱先使用生活化任務語氣，完整主題範圍與 SEO 副標另行整理。
- 「外出中的補擦」分類頁的生活情境卡固定提供 4 張：通勤、辦公室、戶外活動與旅行。
- 四張生活情境卡在手機版採兩欄 × 兩列排列，讓四種情境同時可見；桌面版可依版面寬度排列為兩欄或四欄。
- 每張生活情境卡只放圖示、情境名稱與一句短說明，不放完整文章摘要，以維持 2×2 版面的可讀性。
- 「外出中的補擦」文章清單依實際處理順序排列：補擦時機、補擦方式、容易漏擦部位、生活情境。
- 「流汗或碰水後」分類頁採靜態判斷流程，將流汗、碰水、下雨淋濕與毛巾／衣物擦拭等情境導向對應的處理方向；不新增獨立情境頁。
- 該分類頁的靜態判斷流程採直向三步排列：發生什麼情況 → 先做什麼 → 何時補擦。
- 該直向三步流程使用編號、細連線與小圖示呈現；不延用「出門前準備」的階梯卡，讓不同分類保有各自的視覺辨識度。
- 「回家後與皮膚照顧」分類頁以「回家後三步流程」作為主模組：清潔防曬 → 觀察肌膚狀況 → 基本照顧；後續文章作為延伸閱讀，不取代流程本身。

- 精選區可放小型 UV 播報／編輯提醒資訊條作為脈絡補充，但不取代文章標題、分類與衛教內容。
- 文章頁上方顯示簡短的資料標籤（例如資料來源類型、最近複查日期）；文末再提供可展開的完整來源、適用範圍與複查資訊，兼顧可信度與閱讀節奏。
- 提供文章搜尋與收藏；搜尋／收藏是衛教區的正式功能，不延後到後續版本。
- 收藏狀態只保存在目前裝置／瀏覽器，不要求註冊、不上傳伺服器，也不做跨裝置同步；收藏資料包含在使用者自行建立的加密備份中，還原後可恢復。
- 衛教首頁提供「已收藏」篩選／分頁，與主題分類、搜尋並列；不在全域導覽新增獨立收藏入口。
- PWA 與公開衛教頁都提供站內搜尋，查找文章標題、摘要、主題分類與標籤，不搜尋全文內文；結果以相關文章卡片呈現，兩邊共用同一公開文章索引。
- 衛教搜尋無結果時顯示「找不到相關文章」，提供清除搜尋與六個主題分類入口，並可繼續查看推薦文章；不導向未審核的外部網路搜尋。
- 公開衛教文章提供「分享文章」操作；優先使用 Web Share，瀏覽器不支援時提供「複製連結」。第一版分享文章只分享固定公開 URL，不另外產生文章分享圖片；裝備分享圖片維持獨立功能。
- 公開文章連結採「編輯部封面式連結預覽卡」：使用固定品牌模板，包含 UVAlert 品牌、文章分類、標題、簡短摘要與抽象 UV／生活編輯圖形；第一版以建置／部署時依文章資料產生為原則，不做使用者操作的文章分享圖片，也不需要管理員系統。
- 連結預覽卡與文章內容分開：它只在社群／通訊軟體顯示文章連結的預覽，不取代文章正文、公開 URL 或裝備分享圖片；文章標題、分類或摘要更新時需一併重新產生預覽資料。

### 發布原則

- 每一項健康／安全主張都要能追溯到來源。
- 優先使用台灣政府資料，再使用 WHO 或其它國家的公共衛生／監管機構。
- 外國規範需標示適用司法轄區，不直接當成台灣規定。
- 醫學會資料只能作為補充，不取代官方來源。
- 「淋雨」相關說明必須清楚標成從碰水、沖洗與擦拭原則延伸的實務推論，不能假裝官方有獨立淋雨規則。
- 懷孕、用藥、敏感肌或既有疾病只提供風險提醒與諮詢專業人員的方向，不做個人診斷或治療建議。
- 每篇內容保留來源、來源日期與內部複查日期；沒有證據就不發布。
- 核心文章可離線閱讀，採有版本與審查紀錄的更新；外部連結需要網路。
- 資料過舊或待複查時仍可閱讀，但文章開頭以較弱樣式顯示「本文資料可能需要更新」等提示，並同時列出來源日期與最近複查日期。
- 不做社群貼文、留言或使用者自行發布的衛教內容。

### 衛教內容可發現性（SEO／AEO／GEO）

- 衛教內容納入 SEO、AEO（Answer Engine Optimization）與 GEO（Generative Engine Optimization）規劃；基礎仍是以使用者為中心、原創、可查證、清楚分段的衛教文章，不使用關鍵字堆砌、內容農場或大量重複頁面。
- 每篇文章以一個主要問題／主題為核心，使用描述性標題、清楚的段落與問答式小標；內部保留作者／審查角色與編輯紀錄，但第一版公開頁不顯示個人姓名或審閱者身份，只顯示來源、發布／更新與複查日期、適用範圍與限制。
- 文章可規劃 Article、BreadcrumbList 等適合的結構化資料；FAQ 結構化資料只在頁面上確實呈現可見問答時使用，不把結構化資料當成排名或 AI 引用保證。
- SEO／AEO／GEO 不透過特殊關鍵字或隱藏內容達成；公開索引 URL、canonical、sitemap、內部連結、語意 HTML、圖片替代文字與頁面效能等技術範圍仍待確認是否納入第一版。
- 衛教文章採公開、免登入、可被搜尋引擎索引的穩定文章 URL；Web／PWA 內文章與公開文章使用同一個 canonical 內容來源，公開文章可被直接分享與閱讀。
- 公開衛教文章 URL 採穩定的英文語意 slug（例如 `/learn/how-often-to-reapply-sunscreen`），頁面標題、H1、摘要與正文維持繁體中文；不得使用無意義 ID 或因文案小幅修改而頻繁更換 slug。
- 公開衛教首頁與 PWA 內的衛教首頁同步顯示「編輯部主題導讀」；主題、摘要與文章入口共用同一份專案內容資料，公開頁不加入收藏、Session、產品、位置或其它個人資料。
- 六個衛教主題各建立一個公開、免登入、可索引的分類頁；分類頁需有獨立的繁體中文簡介、清楚標題、文章清單與相關內部連結，不只是沒有額外內容的篩選結果頁，並納入 sitemap。分類頁 URL 採英文語意 slug，例如 `/learn/uv-basics`、`/learn/sunscreen-use`、`/learn/water-sweat`、`/learn/sun-protective-clothing`、`/learn/storage-skin-safety`、`/learn/special-cases-faq`。
- 分類頁採 B+ 共用版型：麵包屑、分類標題／簡介、一篇分類精選、結構化文章清單與相關分類；再依主題加入少量專屬模組，例如 UV 色階／曲線、步驟卡、情境提示卡、比較表或問答清單，不讓六個頁面完全使用不同設計系統。
- 六個分類頁各手動指定一篇分類精選文章；由專案內容資料維護，不自動以最新發布文章取代，也不需要管理員系統。分類頁內的文章清單依使用者任務／常見情境排序，優先回答「現在遇到這個狀況該怎麼做」，不以最新發布日期作為主要排序規則；每篇文章只設定一個主要使用情境，作為卡片上的情境標籤。全站共用一組固定的使用情境詞彙，實際中文標籤文案於所有問題完成後統一潤飾；情境標籤可點擊，點擊後直接篩選全站所有符合該情境的衛教文章，並在同一個衛教首頁內顯示目前情境與「清除篩選」操作；清除後回到衛教首頁的預設狀態。若某個固定情境目前沒有任何文章使用，該情境標籤暫不顯示，避免產生空結果。文章詳細頁也顯示同一個主要情境標籤，並可點擊查看全站相關文章；從文章詳細頁點擊後同樣回到衛教首頁的全站篩選結果，且只有在保留原文章來源時才提供「回到上一頁文章」操作。全站情境篩選結果不顯示文章所屬分類，只保留情境、標題與摘要；同一情境下的文章依實用程度手動排序，先呈現能立即採取行動的內容，再呈現補充與深入內容。使用者開始輸入搜尋文字時，自動清除目前的情境篩選與「已收藏」篩選，改為搜尋全站衛教文章；清除搜尋文字後維持全站未篩選狀態，不自動恢復先前情境或收藏篩選。搜尋結果只有在使用者按下「搜尋」或鍵盤 Enter 後更新，輸入過程不即時變動結果；搜尋至少需要 2 個字，未輸入文字時按下搜尋回到衛教首頁預設狀態；若只輸入 1 個字就送出，在搜尋框下方顯示「請輸入至少 2 個字」提示，不使用彈窗；輸入第 2 個字後或清空搜尋框時，提示立即消失；成功搜尋後保留搜尋文字，並提供清除按鈕；搜尋結果不顯示文章數量；搜尋結果沿用衛教首頁與分類頁的文章卡片樣式，不新增獨立的搜尋卡片；PWA 文章卡片提供小型收藏圖示，公開衛教頁不顯示收藏操作；收藏或取消收藏後僅立即切換圖示狀態，不跳出提示或確認視窗；文章詳細頁不提供收藏操作；「已收藏」篩選結果沿用一般文章卡片，收藏圖示顯示為已收藏狀態；尚未收藏任何文章時顯示「還沒有收藏文章」空狀態，並提供「看看衛教文章」入口，點擊後回到衛教首頁預設狀態。
- 公開衛教頁需排除使用者個人資料、收藏狀態、產品紀錄、Session、位置與任何本機／帳號資料；這些內容仍只存在 Web／PWA 的個人資料流程中。
- 公開文章需納入網站 sitemap、可被爬取且提供可讀取的 HTML；是否採 SSR、預先產生或其它渲染方式留待技術實作階段確認。公開頁不強迫安裝 PWA 或登入。
- 在已安裝的 PWA 內點擊衛教文章時，優先留在同一個 PWA 內的文章路由；從搜尋引擎、外部分享或一般瀏覽器進入時，開啟同一個公開 Web URL。公開頁可提供「在 UVAlert 中開啟」入口，但 Web 平台不能保證作業系統一定把外部連結重新交給已安裝的 PWA。
- 同一個公開衛教 URL 依使用情境採不同頁面外框：已安裝的 PWA 內保留 PWA 下排導覽、收藏與回到衛教操作；一般瀏覽器／搜尋／外部分享進入時使用獨立公開閱讀版面，不顯示個人資料或個人導覽，提供可選的「在 UVAlert 中開啟」。文章正文、來源與 canonical 只維護一份。
- 公開閱讀版不顯示「收藏」按鈕；收藏只在 PWA 內提供，公開頁專注閱讀與分享。公開頁的「在 UVAlert 中開啟」只是選用入口，不要求登入或安裝，未安裝 PWA 時仍可完整閱讀文章。
- 公開文章的「在 UVAlert 中開啟」放在文章內容與完整來源之後，以次要按鈕呈現；不使用開頭阻擋式引導或固定浮動安裝提示。
- 公開搜尋結果頁不列入網站 sitemap；搜尋查詢不建立可被索引的個人或低價值內容頁，公開文章本身仍維持可索引的 canonical URL。
- 衛教文章採版本管理與分級撤回：一般更新維持原公開 URL 並標示更新日期；資料可能過時但仍可參考時保留文章並顯示警告、來源日期與最新相關文章；內容錯誤或可能造成健康風險時隱藏原文，改顯示暫停原因、替代文章、來源與回到衛教入口，並從 sitemap 移除該內容。
- 第一版公開文章不顯示作者／審閱者姓名、職稱或資格；只顯示來源、發布／更新日期、最近複查日期與適用限制，不虛構個人專業背書。
- 文章結尾在完整來源之後顯示 2～3 篇相關文章；推薦依同一主題、標籤或編輯指定產生，不使用收藏、閱讀紀錄或其它個人資料，也不在公開頁建立個人化推薦。
- 公開文章顯示發布日期、最近更新日期與最近複查日期；文章有一般更新時顯示簡短「本文已更新」提示，重要變更可補一行變更方向，但不公開內部版本號或完整版本歷史。
- 「本文已更新」旁提供可展開的變更摘要；摘要預設收合，使用者主動展開後才閱讀重要變更方向，不在文章開頭長篇列出歷史。
- 內容錯誤或有健康風險而撤回時保留原公開 URL，顯示「本文已撤回」頁；頁面標示撤回日期、簡短撤回原因、可用的替代文章、來源／公告與回到防曬衛教入口。原因只說明「需要重新查核／暫停提供」等必要資訊，不重述可能造成誤導的原文。撤回頁設為 `noindex` 並移出 sitemap，不把原文繼續提供給搜尋或 AI 摘要。
- 官方來源連結依閱讀情境處理：PWA 內可沿用目前路由或明確開啟外部來源；公開文章頁以新分頁／新視窗開啟外部來源，保留原文章閱讀位置。所有外部連結顯示來源機構名稱與內容名稱，不使用模糊的「點此查看」。

- 問題回報草稿保存 30 天，草稿列表顯示建立日期與剩餘保存時間；到期自動刪除，使用者也可隨時手動刪除。

- 問題回報成功送出後立即刪除本機草稿與附件，只保留送出結果與回報編號；若送出失敗或取消，則保留草稿供重試。
- 回報編號只供查看與複製，不在 App 內提供回報進度或「我的回報」列表；Email 為選填，填寫後才可用於後續回覆，未填寫時不要求補交聯絡方式。
- 問題回報成功後留在結果頁，顯示成功狀態與回報編號，提供「複製編號」與「回到更多」；不自動跳到提醒頁。

## 16. 說明與關於

- 「更多 → 說明與關於」採單一頁面，不再另外拆出「使用說明」或「關於 UVAlert」兩個入口。
- 頁面分成三個內容區：使用說明／常見問題、資料來源與使用限制、關於 UVAlert。
- 三個內容區採可展開／收合區塊；預設展開「使用說明／常見問題」，「資料來源與使用限制」及「關於 UVAlert」預設收合，避免手機頁面過長。
- 使用說明／常見問題集中解釋核心倒數如何運作、120 分鐘保守預設、通知可能延遲、離線行為與晚上顯示明日 UV 的原因；不取代提醒流程中的必要操作提示。
- 資料來源與使用限制列出 UV 預測與衛教內容的來源、適用範圍與複查資訊，並明確說明 UVAlert 不提供醫療診斷或治療建議。
- 關於 UVAlert 顯示產品用途、版本資訊、開源／第三方素材授權與隱私政策連結；資料同步、備份與資料清除的詳細操作仍連回「本機資料與隱私」，不在此頁重複一份設定流程。
- 需要時可從功能脈絡連到本頁的相關段落，但不在提醒主畫面塞入完整說明、輪播或阻擋式彈窗。

## 17. 顯示與無障礙方向

### 全站視覺概念

- 全站採「防曬氣象管家 × 防曬生活編輯部」的混合概念：即時 UV 與倒數使用氣象播報的資訊可信度，衛教與裝備使用生活編輯部的內容質感。
- 「防曬氣象管家」是提醒頁的視覺／內容概念，不是頁面名稱或下排導覽名稱；正式入口仍使用「提醒」。
- 「防曬生活編輯部」是衛教與裝備的視覺／內容概念，不新增主導覽入口，也不強迫每個頁面使用編輯部命名。
- 「防曬生活編輯部」只作為防曬衛教與裝備內容的設計概念；正式頁面名稱仍為「防曬衛教」，不新增同名導覽入口或路由。
- 提醒頁不顯示額外的大型頁面標題；使用者進入「提醒」後直接看到目前 UV、補擦倒數與主要操作，必要的小標題可放在資訊卡內。
- 全站以暖白／米白／杏桃或珊瑚等生活編輯部色調作為品牌底色；UV 強度只在局部標籤、曲線、指示器與必要狀態中使用對應色階，不讓整張主卡隨 UV 變成警告色。
- UV 色彩不單獨承擔資訊意義；所有強度仍需搭配文字、圖示或數值，並在深色模式、對比與色覺差異下保持可辨識。
- 第一版素材採混合方案：功能頁以一致的線性圖示、UV 圖形與簡潔插畫為主；衛教只加入少量已確認授權的生活照片／編輯式插圖；裝備與分享優先使用使用者主動加入的照片。
- 外部素材需保留來源、授權、可否商用／裁切與必要署名紀錄；沒有圖片或素材載入失敗時，使用固定色塊／圖示備用版型，不讓頁面依賴單一外部圖片。
- 第一版不設定固定人物或女性氣象主播頭像；氣象主播感透過資訊條、UV 圖表、播報層級與親切文案建立。未來若需要增加記憶點，可另行加入少量抽象插畫角色，但不預設納入第一版。

- 主題：跟隨系統／淺色／深色。
- 動畫：尊重系統「減少動態效果」偏好。
- 字體：尊重裝置字級縮放。
- 詳細的鍵盤操作、焦點順序、讀屏標籤、對比與錯誤提示，仍需在 Wireframe 與 UI 規格階段逐頁確認。

## 20. 後續回寫規則

1. 每一個新問題被使用者接受、否決或延後後，先更新本文件。
2. 採雙階段決策檢查：訪談進行中，每個新決定都立即與既有決定交叉比對；若發現矛盾、核心偏移、操作負擔、技術限制或缺少例外狀態，須明確向使用者說明影響並重新確認，不得自行覆寫舊決定。
3. 訪談完成後，再從產品核心、Sitemap、主要 User Flow、例外／復原流程、匿名與離線狀態、技術可行性及 UX 文案一致性進行一次完整總檢查。
4. 完整總檢查後，先產出完整 Sitemap 與 User Flow，檢查入口、返回路徑、空狀態、錯誤狀態與不可達畫面。
5. 接著逐頁整理 Wireframe 所需資訊層級與操作狀態。
6. 最後才統一改寫 UX 文案並回寫 PRD、Screen Inventory、Rule Table、Copy Deck 與技術規格。
7. 正式回寫前逐項比對本文件，避免只更新下游文件或遺漏已否決決策。
