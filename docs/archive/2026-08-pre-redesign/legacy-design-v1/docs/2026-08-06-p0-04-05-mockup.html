為什麼是這樣改

  • 這是「找例外」的任務，不是「做選擇」的任務

    預設組合進來時方法已經全部設好。九成使用者想做的是「其他都對，只有耳朵我戴帽子」。 現況把一個已經回答完的問題又完整問了一次，於是多數人捲完 20 個選項、什麼都沒改就關掉。

  • 四個選項平鋪，本來就違反 PRD §5.2.5

    §5.2.5 明訂：「只提供兩個主要選項：已擦防曬產品、被衣物完整遮住； 其他外用產品放在次要的『其他情況』，不與主要選項競爭」，而且 「不在第一層另列語義模糊的『兩者都有』」。 現況把「衣物下方也有擦防曬」當成第四個並列選項，正是那個被禁止的「兩者都有」。 這是既有的規格落差，不是這輪才發生的。

  • 衣物覆蓋不能刪，它是兩個主要選項之一

    §5.2.5 把它與防曬乳並列為主要選項。刪掉的話，戴防曬袖套的人只能謊報 「已擦防曬」——系統會為一個從未塗抹的部位開始跑 120 分鐘倒數， 再叫他去補擦不存在的東西。RR-P0-CLOTHING-001／ 002 與 TV-009／010／025 也會變成到不了的死碼。

  • AC-34 本來就寫了這個形狀

    「套用組合後建立例外」「只有子部位不同時才展開」。現況在原子部位那層 有照做（沒攤開 8 個細部位），但在方法這層沒有。提案只是把同一個 漸進揭露原則往下再套一層。

  • 不動資料模型

    ZoneProtectionForm 的提交邏輯與合法方法組合規則完全不變， 純粹是揭露層次。因為此元件已裁決由設定與提醒頁共用，改一次兩邊都受益。

步驟 2：「開始提醒」不被內容推走

上面那個 sheet 的按鈕是「完成調整」與「關閉」，不是開始提醒。 真正的開始按鈕在步驟 2 的頁尾，目前是一般流式排版——內容多長，它就被推多遠。 而併入原步驟 3 的內容會讓它更遠。提案是把操作列釘在底部。

捲捲看——按鈕不會跟著跑掉

  • 固定操作列不違反「不得雙層固定按鈕」

    規範禁止的是底部導覽與另一組固定操作列同時出現。設定精靈的 route meta 是 hideNavigation: true，底部導覽本來就藏起來，沒有東西跟它競爭。

  • 摘要壓成一行，是為了讓一般情況一屏結束

    部位不展開成列表，只留一行加「調整」。想看細節或改動的人才進 sheet。 AC-34 要求的是完整摘要有被揭露，不是強迫使用者捲過它。

  • 警示是條件式的，而且排在最前面

    過期、身分未知、異常這些多數 Session 一個都沒有，沒有就不佔位。 真的有的時候放在最上面，是進入畫面第一眼就看到的位置—— 靠版位而不是靠強迫捲動來確保它被看見。

  • 按鈕文字要說出真正會發生的事

    產品身分未確認時不會建立倒數（identity_unconfirmed → 無期限資格）。 此時仍寫「開始提醒」會讓人以為有倒數，所以改成「開始提醒（不建立倒數）」。 S-05 規格本來就要求這種情況必須「明示不建立產品期限」，寫進按鈕是最難忽略的位置。
