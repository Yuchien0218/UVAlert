# 四個規格缺口分析

## 概述

在 2026-08-06 裁決中確定的四項規格變更，目前代碼實現中存在以下缺口：

## 1. 兩步流程（P0 優先級：HIGH）

### 現況
- 設置流程有三個步驟頁面：
  1. `setup-context`（S-03 選擇情境）
  2. `setup-timing`（S-05 產品與時間）
  3. `setup-review`（原 S-06 最終確認）

### 規格要求
- 設置流程應簡化為兩步
- S-06 最終確認頁廢除，其內容併入 S-05
- S-05 頁面要求：
  - 按鈕改為 `開始提醒`（計時起點）
  - 必須顯示完整部位摘要、防護方式、產品、塗抹時間
  - 摘要改在同一畫面的按鈕上方

### 實施範圍
- [ ] 修改 SetupReviewPage → 摘要區塊（可復用元件）
- [ ] 整合摘要到 SetupTimingPage
- [ ] 移除 setup-review 路由
- [ ] 更新 setup-timing 步驟標記（改為 step 2）
- [ ] 調整路由守卫邏輯
- [ ] 測試整個設置流程

### 相關文件
- `apps/web/src/pages/setup/SetupTimingPage.vue` 第 61 行
- `apps/web/src/pages/setup/SetupReviewPage.vue` - 整個檔案
- `apps/web/src/router/index.ts` 第 72-101 行
- `apps/web/src/features/setup/createSetupController.ts`

### 驗收標準
- AC-34 Scenario C：確認有被揭露（不是被查看，只是不能跳過）
- 流程步數正確顯示為 2/2
- 完整摘要在同一頁面可見

## 2. S-04 揭露層次（P0 優先級：HIGH）

### 現況
- `ZoneProtectionForm` 實現把四個選項並列成第一層
- 每個部位群組常駐一組單選鈕
- 實測現況：20 個常駐可見單選鈕、需捲動 3 屏才能離開本區

### 規格要求
三層揭露層次：

| 層次 | 內容 | 常駐可見單選鈕 |
| --- | --- | --- |
| 收合（預設） | 每個部位群組一行：群組名稱＋目前方法的狀態文字 | **0 個** |
| 點開一組 | 只顯示兩個主要選項 + `其他情況` 文字連結 | **2 個** |
| 展開 `其他情況` | 才出現 `其他外用產品` | **3 個** |

### 規則
- [ ] 預設收合，無任何可見單選鈕
- [ ] 一次只展開一個群組
- [ ] 選 `已擦防曬產品` 後直接收合
- [ ] 選 `被衣物完整遮住` 後不立即收合，顯示選填追問
- [ ] `衣物下方也有擦防曬產品` 不得放進第一層
- [ ] 衣物覆蓋狀態文字不得使用 untimed 紫色
- [ ] 按 `完成` 按鈕才收起

### 實施範圍
- [ ] 重新設計 `ZoneProtectionForm` UI 邏輯
- [ ] 實現群組收合／展開狀態管理
- [ ] 調整選項顯示層級
- [ ] 更新追問邏輯（衣物下方防曬產品）
- [ ] 狀態文字色彩調整
- [ ] 完整的單元測試

### 相關文件
- `apps/web/src/components/setup/ZoneProtectionForm.vue`
- `P0_SCREEN_INVENTORY.md` 第 360-420 行

### 驗收標準
- AC-26、34、52、79、81、88、94
- 捲動次數從 3 屏減少到 1 屏以內
- 單選鈕數量從 20 個減少到 0-3 個常駐

## 3. gearCategory 裝備分類（P0 優先級：MEDIUM）

### 現況
- 產品模型中無 `gearCategory` 字段
- 所有產品都視為防曬產品處理

### 規格要求
新增 `gearCategory` 字段，四種品類：

| 品類 | 是否進 reducer | 提醒語意 |
| --- | --- | --- |
| `sunscreen` | **是** | 到期、耐水、補擦間隔、曝曬前等待都影響倒數 |
| `clothing` | **部分** | 是 methodComponent，覆蓋期間不倒數 |
| `eyewear` | 否 | 無對應 `BODY_ZONE`，純紀錄 |
| `other_gear` | 否 | 純紀錄 |

### 實施範圍
- [ ] 在 `@sunshield/contracts` 中定義 `gearCategory` schema
- [ ] 更新 `ProductCatalogRecordV1` 類型
- [ ] 在 UI 中新增品類選擇
- [ ] 調整 reducer 邏輯（只 sunscreen 進）
- [ ] S-11、S-12、S-13 中實現品類管理
- [ ] 新欄位遷移邏輯（purchaseMonth、expiryDate、note、archivedAt）

### 相關文件
- `packages/contracts/src/product.ts`
- `P0_SCREEN_INVENTORY.md` 第 867-973 行（S-11、S-12、S-13）

### 驗收標準
- AC-35、43、47、48、50、53、55、97
- 產品、衣物、墨鏡、其他裝備能分別記錄
- UI 明示哪些欄位會影響倒數

## 優先級與工作量評估

### 優先級排序（按對 P0 完整性的影響）

1. **兩步流程** - HIGH（影響核心用戶流程）
   - 預計 8 小時
   - 可能影響多個測試用例

2. **S-04 揭露層次** - HIGH（影響可用性指標）
   - 預計 12 小時
   - UI 重構，需要詳細測試

3. **gearCategory** - MEDIUM（新功能，不影響現有流程）
   - 預計 6 小時
   - 主要影響 S-11～S-13 實施

4. **/help** - MEDIUM（信息頁面，不影響核心功能）
   - 預計 4 小時
   - 主要是內容集成

### 總工作量
- 合計：30 小時
- 建議分批實施，先完成流程級別的改動（1、2），再做功能擴展（3、4）
