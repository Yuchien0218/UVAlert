# P0 設計約束清單（重新設計前必讀）

**用途**：交給設計端。這份清單列出的不是美感偏好，是 **P0 驗收條件**——
違反其中任一條，畫面再好看也無法通過發布。

**來源**：`防曬晴報員PRD.md` §5.7.7、AC-34、AC-65～AC-71；
`P0_SCREEN_INVENTORY.md` S-18。每條後面標了出處，可回查原文。

**適用範圍**：首頁、提醒頁、設定流程、部位狀態、產品頁。

---

## 一、最容易被誤砍的六條

重新設計時最常被當成「舊版設計決定」而拿掉的，其實都是硬約束。

### 1. 綠色不得表示安全 〔AC-66、AC-69、§5.7.7〕

- 不得以綠色表示「安全」「防護有效」「完成後無風險」。
- 不得把提醒環稱為防護量或安全百分比。
- **理由**：這是產品的核心安全立場——系統只記錄使用者自陳，
  從未驗證防護是否充分。綠色會製造未經證實的安全感。

### 2. 狀態不能只靠顏色 〔AC-69〕

每個狀態都必須同時具備 **色彩＋圖示＋文字**（適用時再加原因）：

| 狀態 | 規格指定的組合 |
| --- | --- |
| 提醒進行中 | 藍紫＋時鐘圖示 |
| 即將需要檢查 | 深琥珀文字／邊框＋提醒圖示 |
| 建議現在檢查／補擦 | 深紅文字／邊框＋驚嘆圖示 |
| 尚未記錄／不確定 | 灰藍＋問號或虛線輪廓 |
| 衣物／遮蔽 | 深藍灰＋衣服、帽子或陽傘圖示 |

**驗收方式**：以灰階或色覺差異模擬檢視，仍能分辨每一個狀態。

### 3. 摘要必須在按鈕上方，且不得摺疊 〔AC-34〕

設定流程步驟 2 的確認摘要**不得**做成可收合區塊或另開 sheet。

**理由**：快速提醒會自動寫入建議部位，使用者沒有逐一挑選過，
所以這份摘要是唯一的揭露點。摺疊等同於「系統加入了未揭露的內容」。

必顯五項：情境與水上狀態、追蹤部位、產品包裝標示、
產品資格警示、「不代表安全曝曬時間」。

### 4. 次要 CTA 排在主要操作之後 〔AC-65〕

- 主要按鈕至少 **44 CSS px** 高。
- 主要／次要不得只以顏色深淺區分；次要按鈕須有至少 **2 CSS px 邊框**。
- 急症相關的主要行動永遠優先，不得被一般免責聲明或次要內容延後。

### 5. 警示排在版面最前，沒有警示時不佔版位 〔S-05〕

產品過期／異常／不適／身分未知／非防曬的警示必須排在最前，
但**不得**留一個常駐的空警示區。

### 6. untimed 的紫色有語意 〔S-04 裁決〕

紫色在本專案代表「沒有可信期限、需要處理」。
中性或正常狀態借用它，會讓使用者以為出了問題。

## 二、日間高對比 token（§5.7.7）

P0 預設使用高對比淺色介面，優先確保**陽光直射、樹蔭、低亮度、
霧面／防窺保護貼、配戴太陽眼鏡**時仍可辨識。

> 不得以室內設計稿看起來柔和作為降低對比的理由。

| token | 用途 | 色碼 | 對比／限制 |
| --- | --- | --- | --- |
| `surface.page` | 頁面背景 | `#FFFDF7` | 溫暖米白；不放背景照片或低對比漸層 |
| `surface.card` | 卡片背景 | `#FFFFFF` | 卡片不透明；重要邊界不可只靠陰影 |
| `text.primary` | 主要文字 | `#172033` | 對頁面約 15.99:1 |
| `text.secondary` | 次要文字 | `#5F6B7A` | 約 5.33:1；**不得再以 opacity 降低** |
| `brand.primary` | 主要按鈕／品牌 | `#233B6E` | 白字對比約 10.92:1 |
| `status.tracking` | 提醒進行中 | `#3C5AA9` | 約 6.40:1；**不得稱為安全** |
| `status.soon.text` | 即將檢查 | `#8B5A00` | 搭 `#FFF4CC`；**亮黃不得承載白字** |
| `status.due.text` | 建議現在處理 | `#9B2C2C` | 搭 `#FDE8E7`；**不得整頁閃紅** |
| `status.unknown` | 尚未記錄／不確定 | `#5F6B7A` | 搭 `#F2F4F7`，另加問號或虛線 |
| `border.strong` | 圓環輪廓／重要邊框 | `#7A8497` | 約 3.70:1 |

### 明確禁止的做法

- 白字搭亮黃／淺橘
- 低透明度文字、細淡灰字
- 文字直接疊在照片上
- 大面積毛玻璃
- 只靠陰影分隔卡片
- 低對比粉彩按鈕

## 三、提醒環與字體下限（§5.7.7）

**提醒環**
- 主要進度用 `status.tracking`，輪廓用 `border.strong`
- 線寬 **12–16 CSS px**；手機直徑目標 **200–240 CSS px**
- 中央保留相對時間、絕對時間、語意標籤
- 到期改用**靜態**卡片＋圖示＋文字，**不閃爍**
- 剩餘軌可用較淡裝飾色，但有意義的進度與總輪廓須符合非文字對比

**字體最低規格**

| 元素 | 尺寸／字重 |
| --- | --- |
| 圓環主要時間 | 44–56 px／700 |
| 狀態標題 | 20–24 px／700 |
| 一般文字 | ≥16 px／400–500 |
| 按鈕 | 16–18 px／600 |
| 必要次要說明 | ≥14 px／500 |
| 重要圖示筆畫 | ≥2 px |

文字放大 **200%** 時不得截斷主要狀態、時間與操作。

## 四、動態與無障礙 〔AC-67〕

- 螢幕閱讀器取得白話剩餘時間與狀態，但**不逐秒朗讀**。
- `prefers-reduced-motion` 下**無旋轉、脈衝或閃爍**，
  所有重要資訊仍可由文字與圖示理解。
- 到期後不顯示負數、不持續閃爍 `00:00`、不暫停、不任意增加時間。

---

## 五、三種顯示模式 〔AC-70、S-18〕

規格名稱為 `跟隨手機`、`日間高對比`、`夜間模式`。

- 三種模式**核心內容與功能相同**。
- 夜間色票須**另行**通過相同的文字與非文字對比驗證，
  **不得用簡單反相產生**。
- 不得依賴 Ambient Light Sensor 自動切換。
- 設定保存於本機並立即套用，不要求定位或環境光權限。

---

## 六、戶外實機驗收 〔AC-71〕

這條不是桌機檢查，是**實機測試**：

- 代表性 Android／iPhone，正午直射陽光或樹蔭
- 涵蓋 PRD §17.3.1 的亮度、保護貼、眼鏡條件
- 任務：UVI 判讀、主要狀態、部位狀態、`記錄已補擦`／`回報狀況`、模式切換

**通過條件**：不需猜測顏色、不需橫向捲動、不需遮住螢幕才找得到必要資訊。
失敗條件與修訂決策須留存；未完成不得宣稱適合戶外閱讀。

## 七、目前實作與規格的落差（重新設計時一併修正）

### ⚠️ 首次使用的預設模式不符規格

- **規格**（§5.7.7、S-18）：首次使用預設 `日間高對比`，
  使用者可改為跟隨手機；**日間淺色方案是戶外測試與發布基準**。
- **現況**：`createAppearanceController.ts` 讀不到既有偏好時回傳 `system`，
  在深色手機上會直接進暗色。
- **影響**：AC-68 的 Given 是「首次開啟服務或選擇日間高對比」，
  目前首次開啟不必然落在該情境。

### ⚠️ 模式命名與規格不一致

- **規格**：`跟隨手機`／`日間高對比`／`夜間模式`
- **現況**：淺色／深色／跟隨系統

「淺色」不等於「日間高對比」——後者是 §5.7.7 那組特定 token，
不是任意的亮色主題。命名一致才不會在驗收時各說各話。

### ⚠️ 尚未套用 §5.7.7 token

目前使用的是自訂 CSS 變數，未對應規格 token 名稱與色碼。
重新設計正好是導入的時機。

## 八、重畫時可以自由發揮的部分

以下不受 P0 驗收約束，設計端可自行決定：

- 版面網格、間距尺度、圓角、陰影強度（但卡片邊界不可只靠陰影）
- 圖示風格（但需維持狀態語意與 ≥2 px 筆畫）
- 字體家族（但需符合上述尺寸下限）
- 動效節奏（但需遵守 reduced-motion 與不閃爍）
- 插圖與空狀態的視覺語言

---

## 九、給設計端的一句話總結

> 這是一個**戶外、單手、陽光下**使用的安全工具。
> 它必須看起來可信但**不製造安全感**；
> 每個狀態都要在灰階下仍然可辨識；
> 摘要與警示不能為了版面美觀而被收起來。
